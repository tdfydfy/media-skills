# 素材点：透明贴片的结构单元

素材是"点缀"：一块板只在一个瞬间出现，说完就退。

---

## 一、只有四个位置值得做素材

**不是每句话都要呼应。** 全片上万字，能做成素材的只有这四类地方：

| `kind` | 什么时候 | 组件族 |
|---|---|---|
| `chapter` | 章节切换 —— 原片说"接下来讲第二点" | `c-capsule` `c-step` |
| `concept` | 关键概念首次出现，需要钉住定义 | `c-kw` `c-note` `c-quote` `c-rule` |
| `data` | 报了数字 / 占比 / 对比 | `c-data` `c-bar` `c-ring` `c-cmp` `c-flow` `c-stack` `c-line` |
| `image` | 原片提到画面里看不见的东西（架构图、位置、面貌） | `c-flow` `c-stack` + 图形元素 |

判据很简单：**这句话如果只是听起来顺，就不要做素材。**
一块板占掉观众 3 秒注意力，得换来"哦，原来是这样"。

---

## 二、为什么时间必须量、空档必须留

素材贴的是别人已经拍好的画面：你说"第 12 秒出现"，原片第 12 秒说的就必须是那句。
按 `字数 / 4.5` 估出来的秒贴上去，偏差可以到十几秒。

空档 ≥1.5s 同时是两件事 —— **让这块板不被误读成"第二块屏"**，
以及**给用户的剪辑留出呼吸位**（他要能在自己的时间线上挪动、错位、对齐）。

---

## 三、为什么画布恒为 3:4 竖版

1. **3:4 是"一块板"，9:16 是"整个屏"。** 素材要嵌进别人的画面里，不是画面本身 ——
   3:4 放进 9:16 的成片里左右还留有余地，放进 16:9 里也不至于高得离谱，是**跨画幅通用**的形状。
2. **竖排 = 时间顺序 = 因果顺序。** 人读竖列天然按"先→后"读，
   所以「A → B」的转化关系在竖版里是零成本的。
3. **素材是给"摆"的，不是给"看"的。** 用户会把它缩小放到画面一角，
   元素竖着排成一列才看得清。

**所以元素竖排。** 横着铺满的写法在 3:4 里一定溢出。

---

## 四、关系的几种形态

| 关系 | 画法 | 适合口播 | 组件 |
|---|---|---|---|
| 转化 | 上下两块 + 箭头 | "从 A 变成 B" | `c-flow` |
| 对比 | 上下两块 + 中间分隔线 | "不是 A，是 B" | `c-cmp` |
| 递进 | 三块竖向 + 序号 | "第一…第二…第三…" | `c-stack` |
| 占比 | 一条棒 + 分段标签 | "其中 A 占 x%" | `c-bar` |
| 因果 | 上块 + 下块 + 因果符 | "因为 A，所以 B" | `c-flow` + 因果标签 |

**一个素材最多 3 个元素 + 2 组关系。** 再多，用户缩到画面一角就看不见了。

`elements[].role` 允许值：

| `role` | 是什么 |
|---|---|
| `st` | 块（一个具体信息点，带 `t` 与可选 `v`） |
| `arrow` | 箭头（可选 `label` 写关系名） |
| `sep` | 分隔线 |
| `kw` | 关键词 |
| `line` | 引线 |
| `txt` | 说明文字 |

## 五、常见错误

| 症状 | 病因 | 修法 |
|---|---|---|
| 一块板只有一个孤零零的数字 | 缺关系层 | 补一个对照 / 起点值 |
| 一块板塞了 5 个元素 | 超规模上限 | 拆成两个素材 |
| 元素横着铺满 | 按 9:16 排的 | 改竖排 |
| 数字在原片说完之前就出现 | 锚点用了 `sync` / `head` | 改 `tail` |
| 连着十几秒一直有贴片 | 空档不足 | 留 ≥1.5s 纯透明 |
| 每个数字都做了素材 | 没有取舍 | 只留推动论证的那个 |
| 素材念出来和口播一样 | 直接转录 SRT | 只留名词与数字 |
| 剧情片贴了 12 个素材 | 密度档用错 | `drama` 是 3~5 个/60s |
