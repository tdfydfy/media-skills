# 写脚本 · 透明素材（第 1 环 B 支线）

**把文字变成 `purpose="overlay"` 的脚本 JSON。** 产出 `脚本.json` + 一份给人看的同名 `.md`，交给下游 `ivh-overlay`。你的边界就是那份 JSON。

```
宿主视频的音轨（别人的口播）+ 文稿 / SRT
        ↓   ← 你在这里（贴在别人画面上的稀疏贴片）
   脚本.json  ──→ ivh-overlay ──→ ivh-render ──→ .mov (ProRes 4444 + alpha)
```

产物形态是**点缀**：画面不铺满，只挑几处值得停一眼的地方，一块板在一个瞬间出现、说完就退。

**闸门 1 / 2 在本技能。** `脚本.json` + `脚本.md` 出来之后：跑校验盖章 → `present_files` 递出去
→ **本轮结束**。等用户看过说"可以"，排版才轮到 `ivh-overlay`。
用户一次性要的是最终视频，也照停 —— 闸门是分工：字没定，排版就是白排。

## 零、先问，别猜

| # | 要问的 | 为什么必须先定 |
|---|---|---|
| 1 | **宿主音轨在哪？** SRT / 音频 / 视频文件 | 素材点的秒要跟对方的口播走，没有音轨就没有时间基准 |
| 2 | **风格**（六选一，让用户选） | 决定字号容字量，写完再换要回头重写字 |
| 3 | 用户自己会剪吗？ | 决定留多少空档 —— 空档是给剪辑留的手感 |

**时间码永远是量出来的。** 拿到音频/视频先转 SRT（或 ASR）；连音轨都拿不到时先停下问用户要。

`contentType`（原片体裁）自己判，判完写进 `meta`。它决定本片的**贴片密度**：

| `contentType` | 原片长什么样 | 每 60s 素材点 |
|---|---|---|
| `data` | 研报 / 口播 / 复盘 | **8~12** |
| `narrative` | 故事 / 案例 / 科普 | **4~7** |
| `drama` | 剧情 / 短剧 | **3~5** |
| `opinion` | 观点 / 评论 | **5~8** |

每个体裁该圈什么当抓手，见 `../ivh-script-core/distillation.md`。
选错不会报错，只会静默变差：拿数据型规则去筛剧情稿，候选句一条都挑不出来。

## 一、结构：素材点（`points[]`）

```
points[]   kind: chapter → concept → data → image   （四类位置，决定组件族）
             start/end  绝对秒，来自宿主音轨
             comp       组件类名（关系型优先）
             elements   一组元素 + 它们的关系（2~3 个）
             anim/outAnim 入场 / 退场
```

| 字段 | 本支线要点 |
|---|---|
| `start` / `end` | 停留 **≥0.8s**，理想 **2.5~4.5s** |
| `comp` | **关系型优先**：`c-flow` / `c-stack` / `c-cmp`（竖版原生） |
| `elements` | **2~3 个**，且必须含关系层 |

字段全貌与硬规则见 `../ivh-script-core/script-format.md` §一/§二。
四类位置怎么认、3:4 画布为什么、关系的五种形态、规模上限见 `references/points.md`。

## 二、密度：稀疏、独立

| | 值 |
|---|---|
| 一个素材点停留 | **≥0.8s**，理想 **2.5~4.5s** |
| 相邻点之间 | **≥1.5s 纯透明空档** |
| 全片总量 | 按 `contentType` 分档（见上表） |
| 同一时刻 | 只有一组元素 |

**空档 ≥1.5s 是硬线。** 它是这块板不被误当成"第二块屏"的全部理由，也是用户在自己的时间线上挪动、错位的余地。

**素材是给"摆"的，不是给"看"的。**

---

## 三、一个素材 = 一组元素 + 它们的关系

一块板上只有一个孤立的数字，那是**字幕卡**：口播已经说了，屏幕上再来一遍就是纯重复。

放上「A → B」的转化，它才承担了口播里"因为…所以…"那一层 —— **关系由画面承担，句子由口播承担。**

| 关系 | 画法 | 适合口播 | 组件 |
|---|---|---|---|
| 转化 | 上下两块 + 箭头 | "从 A 变成 B" | `c-flow` |
| 对比 | 上下两块 + 中间分隔线 | "不是 A，是 B" | `c-cmp` |
| 递进 | 三块竖向 + 序号 | "第一…第二…第三…" | `c-stack` |
| 占比 | 一条棒 + 分段标签 | "其中 A 占 x%" | `c-bar` |

---

## 四、锚点：数字 / 结论一律 `tail`

`parse-srt.mjs --candidates` 给三个入点，本支线的默认只有一个：

| 类型 | 用什么 |
|---|---|
| 数字 / 结论 | **`tail`**（句尾 +0.30） |
| 结构 / 预告 | `head`（罕见，仅当原片明说"下面讲三点"） |
| 概念 / 名词 | `sync`（首次出现的新名词） |

贴片只活 3~5 秒，**提前出现就是剧透**：观众还没听到数字，先看到了数字。所以 `--anchor` 从工具给的值里挑，不要自己发明偏移量。

## 五、提炼与交付

压缩链（抓手 → 论点 → 主张 → 屏幕字）与 `standalone` 相同，方法与判据见 `../ivh-script-core/distillation.md`；每个位置先写 **5 个候选**再挑 1 个。
`comp` 只填类名，15 个组件与按口播信号倒查的选型表见 `../ivh-script-core/chart-choices.md`。

**1. 跑机器校验，并且盖章：**

```bash
node ../ivh-script-core/scripts/check-script.mjs 脚本.json --stamp
```

它会查契约硬规则 + `overlay` 形态锁定（`ratio=3:4` / `bg=transparent`）+ 空档 ≥1.5s + 元素 ≤3 + 全部第 1 环规则。**不过不许交付。**

`--stamp` 把 `{pass, fails, notes, hash}` 写进 `meta.check`，`ivh-overlay` 开跑前验这个章。

**闸门 1 / 2 —— 文本确认。** 校验过了之后的动作是固定的三步：

1. `present_files` 把 `.md` 递过去
2. `.md` 里要有一节 **「候选与选择」**：每个素材点列出 5 个候选、标出选了哪个、为什么 ——
   用户能一眼看出这些字是"挑"出来的还是"想"出来的
3. **本轮到此结束** —— 排版是下一环的活，等用户说"可以"再进 `ivh-overlay`

闸门 2 是 HTML 效果（`ivh-overlay`）；过了就交给 `ivh-render`，那一环只管出片。

## 六、自检

- [ ] `purpose` 是 `overlay`，`points` 非空、`scenes` 为空
- [ ] `contentType` 判对了，密度落在对应档位
- [ ] 时间码来自宿主音轨
- [ ] 每点停留 ≥0.8s；相邻空档 ≥1.5s
- [ ] 每个 `elements` 有 **2~3 个**元素，且**含关系层**
- [ ] 数字型一律 `tail`
- [ ] 校验器跑过、盖了章，`.md` 里贴的是**原始输出**
