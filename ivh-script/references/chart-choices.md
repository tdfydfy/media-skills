# 可视化选型与组件映射

脚本里要写 `broll.comp` / `points[].comp`，所以 `ivh-script` 必须知道下游有哪些组件可用。
这份是**选型索引**：只列名字、用途、门槛，不管怎么画（那是 ②③ 的事）。

## 一、先选技术路线

下游产物是**单文件 HTML、零外部依赖**（校验脚本第 2 项会拦）。所以任何第三方库
都必须**内联**进产物。按这个前提排优先级：

| 优先级 | 路线 | 什么时候用 | 体积代价 |
|---|---|---|---|
| 1（首选） | **纯 CSS + 内联 SVG** | 柱 / 环 / 折线 / 流程 / 对比 —— **九成场景够用** | 0 |
| 2 | 内联 D3 子集（只打包用到的模块） | 需要真正的坐标轴、力导向、复杂多序列图 | 几十~上百 KB |
| 3 | 内联 Lottie JSON + 轻量播放器 | 已经有现成的高质量动效素材（AE 导出） | 通常 >200 KB |

**默认走路线 1。** 信息图视频里的绝大多数图形（一根柱子、一个圈、一条趋势线）
手写 SVG 比引库更快、更可控，动效也更好对齐时间轴。

**什么时候才升级到 D3：** 数据维度 ≥3、需要动态刻度、或者要做用户看得出"这是真图表"的
多序列对比。这时在脚本里标清楚 `viz: "d3"`，并把**数据结构**写全，别让下游猜。

**Lottie 的注意点：** 它的动效由自己的时间轴驱动，**和外部的 `data-in` 卡不住**。
真要用，只用在独立成片的 A-roll 背景层（`standalone`），**不要用在 `overlay` 素材上** ——
素材必须能被 `data-in` / `data-out` 精确切片。

## 二、可选技术标签

脚本里用一个可选字段 `viz` 记录（不加就等于"纯 CSS/SVG"）：

| `viz` | 含义 |
|---|---|
| 省略 | 纯 CSS + 内联 SVG（默认） |
| `d3` | 需要 D3 子集，必须把数据写成 `data.series` 数组 |
| `lottie` | 需要播放 Lottie，必须给 `data.src`（相对路径） |

## 三、组件索引（15 种）

类名一律 `c-` 前缀。`comp` 字段填这里的类名，**只填类名，不写坐标不写样式**。

### 信息卡类 —— 承载一个信息点

| 类名 | 表达什么 | 数据形态 | 适配画幅 |
|---|---|---|---|
| `c-data` | 一个超大数字 + 归因标签 | `to` / `prefix` / `suffix` / `dec` / `k` | 通用 |
| `c-bar` | 横向柱状对比（2~4 条） | `rows[{label, value, color?}]` | 通用 |
| `c-ring` | 环形占比 / 完成度 | `pct` + `cap` | 通用（竖版慎用） |
| `c-line` | 折线趋势 | `series[{x, y}]` 或 `path` | 横版优先 |
| `c-list` | 清单，逐条 | `items[]`，每条 ≤14 字 | 通用 |
| `c-vs` | 一句话级对比 `A ≠ B` | `left` / `right` | 通用 |
| `c-cmp` | 上下两块的数值对照 | `a{label,value}` / `b{label,value}` | **竖版原生** |
| `c-flow` | 上→下转化（含箭头与关系标签） | `from` / `to` / `relation` | **竖版原生** |
| `c-stack` | 竖向递进（三块 + 序号） | `layers[{no, text}]`，≤3 层 | **竖版原生** |

### 文字类 —— 承载主张或语气

| 类名 | 表达什么 | 字数上限 |
|---|---|---|
| `c-kw` | 关键词大字，无容器 | ≤8 字 |
| `c-quote` | 引述 / 金句，竖线 + 斜体 | ≤24 字 |
| `c-rule` | 强调下划线，短句高亮 | ≤14 字 |
| `c-note` | 便签，补充信息 | ≤30 字 |

### 导航类 —— 告诉观众"讲到哪了"

| 类名 | 表达什么 | 字数上限 |
|---|---|---|
| `c-capsule` | 胶囊标签，短归因 | **≤6 字** |
| `c-step` | 步骤编号 | ≤8 字 |

## 四、怎么选

按**口播在说什么**倒推：

| 口播信号 | 选谁 |
|---|---|
| "增长了 37%" / "达到 1.2 亿" | `c-data` |
| "A 比 B 高" / "其中三线占一半" | `c-bar` |
| "完成了六成" / "覆盖率 62%" | `c-ring` |
| "从 2023 到 2026 一路走高" | `c-line`（`viz: d3` 若要多序列） |
| "三个原因：第一…第二…第三…" | `c-list` 或 `c-stack`（竖向递进） |
| "不是 A，是 B" | `c-vs`（一句话）或 `c-cmp`（带数值） |
| "从 A 变成 B" | `c-flow` |
| "所谓 X，就是…" | `c-kw` + `c-note` |
| 金句 / 结论 | `c-quote` |
| "第一部分" / "接下来" | `c-capsule` |

**不要一个组件用到死。** 每 3 个组件至少换 1 种样式。
`standalone` 里全是 `c-data` 会非常单调；`overlay` 里连着两块 `c-cmp` 也一样。

## 五、自检

- [ ] 每个 `comp` 都是上表里的合法类名
- [ ] 数字类组件都写了**参照物**（同比 / 去年值 / 基数），不是孤零零一个百分数
- [ ] 竖版素材优先用 `c-flow` / `c-stack` / `c-cmp` 这三个竖版原生组件
- [ ] 需要坐标轴或多序列时才标 `viz: "d3"`，并写全 `data.series`
- [ ] `overlay` 里没有 `viz: "lottie"`
- [ ] 同一段里组件样式有变化，不是一条道走到黑
