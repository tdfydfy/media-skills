# 提炼法：从原文到屏幕字

**这份讲「怎么把一段话压成一句话」，`two-track-text.md` 讲「压出来的字该长什么样」。**

## 一、什么叫「提炼」

评价一条片子的脚本，只看两件事：

| | 问法 | 不合格的样子 |
|---|---|---|
| **概括度** | 只看 4 条标题、按顺序读，能不能读出一段论证？ | 读出来是一份**目录**：「背景 → 现状 → 问题 → 总结」 |
| **爆发点** | 有没有哪一句让人「咯噔」一下？ | 每句都对，但每句都在意料之中 |

**判据（用它自查，不用感觉）**：把全片的屏幕字摘出来连成一段，读一遍 ——
如果读起来像**大纲**，就是没提炼；如果读起来像**一段话**，才叫提炼。

> 目录型是默认结果。人写脚本时天然会写目录，因为目录最安全 ——
> 它对每句话都成立，所以它对观众什么也没说。

看一个真实的反差。原文（60 字）：

> 我们测算过，只靠一线城市，到明年大概只能覆盖四成用户；但把渠道下沉到三四线，这个数字会翻到七成以上。

| | 屏幕字 | 读起来 |
|---|---|---|
| 目录型 | 渠道策略 / 市场分析 / 结论 | 一份目录 |
| 提炼后 | **一线 40% → 三四线 70%** | 一句话，且是原文那句话 |

两版**信息量相同**，区别只在有没有做完压缩。目录型的病不在「写太少」，在**没压缩**：
它把「渠道策略」这种分类名当成了内容。

## 二、压缩链：四步，每步只做一件事

```
原文 / 口播稿
   ↓ ① 抓手     圈出可量化、可对比的东西
   ↓ ② 论点     它们合起来说明什么（一句话，带因果）
   ↓ ③ 主张     这句话的反面成立吗？成立就退回 ②
   ↓ ④ 屏幕字   压到 ≤2 行 × ≤12 字，剥掉连接词与主语
```

| 步 | 动作（问自己） | 产出 | 过关判据 |
|---|---|---|---|
| ① 抓手 | 这段里有哪些**数字 / 时间 / 对比 / 代价**？ | 一个清单 | 一个都没有 → 这段话做不成画面，先去找数字 |
| ② 论点 | 这些抓手合起来说明什么？ | 一句带因果的话 | 说出来别人能听懂「所以呢」 |
| ③ 主张 | **有没有人会不同意这句话？** | 一句可以被反驳的话 | 没人会反对 = 废话，退回 ② |
| ④ 屏幕字 | 怎么用最少的字摆出这个主张？ | ≤2 行 × ≤12 字 | 不写主语、不写连接词，只留对比的两端 |

**第 ③ 步是分水岭。**「渠道下沉很重要」没人会反对 —— 它就不是主张，是共识。
「一线见顶，增量全在三四线」有人会反对（三四线客单价低）—— 它才是主张，才有劲。

> 换句话说：**主张是要付代价的判断**。没有代价的判断是描述，描述不该占满屏。

### 一个完整的四步走

原文：

> 我们原来以为三四线用户的付费能力不行，所以一直没敢往下走。结果今年一组数据把结论推翻了：三四线的转化率比一线高 1.8 倍，而获客成本只有一半。

| 步 | 结果 |
|---|---|
| ① 抓手 | 转化率 1.8 倍 / 获客成本 1/2 / 「原来以为…结果推翻」 |
| ② 论点 | 三四线的转化与成本都比一线好，与直觉相反 |
| ③ 主张 | **不是付费能力不行，是一直没去试**（可被反驳：样本/口径） |
| ④ 屏幕字 | `三四线转化 1.8 倍` / `获客成本 少一半` |

注意 ③ 用的是**「不是 A，是 B」**结构 —— 它天然带主张，因为它排除了一种说法。

## 三、主张的四条检验

写不出主张时，用这四条筛，一条不过就重写：

| 检验 | 问法 | 不合格 |
|---|---|---|
| **可反驳** | 有人会不同意吗？ | 「渠道很重要」 |
| **有代价** | 它换来了什么、又付出了什么？ | 「要重视渠道下沉」 |
| **有刻度** | 有数字 / 时间 / 程度吗？ | 「效果会更好」 |
| **一口气** | 能一口气说完吗？ | 三行以上的长句 |

四条里**「有刻度」最好补**：找到一个数字，标题立刻从抽象变成具体。
这也是为什么 `check-script.mjs` 会单独报「带数字的屏幕字占比」——
它是最省力的提炼动作，省掉它通常意味着整份脚本都没落地。

## 四、爆发点：钩子放哪、放几个

一条片子只需要 **1 个钩子 + 1 句金句**。多了等于没有。

### 开场（前三秒）

| 类型 | 句式 | 例 |
|---|---|---|
| 反常识 | 不是 A，是 B | `不是没人买，是没人敢推` |
| 代价 | A 的代价是 B | `省下的渠道费，都赔在了复购上` |
| 反差数字 | X 对 Y | `40% 的天花板` |
| 提问 | 为什么 X 却 Y？ | `为什么越下沉越赚钱？` |

**不要用「大家好」「今天我们来讲」开场。** 那是主持人的台词，不是内容 ——
观众在前三秒判断的只有一件事：**这条和我有关吗**。

### 中段：每个数字后面跟一句「所以呢」

数字本身不构成爆发点（`+37%` 到处都是），**反差**才是。
所以数字型素材点最好带参照：`54%（去年 21%）` 而不是 `54%`。
（这条在 `two-track-text.md` 第四节已经写了，这里是它的方法论原因。）

### 收尾：金句

合格标准：**能脱离这条视频单独发出去**。

- ✅ `往下走，才有增量` · `不是没需求，是没在场`
- ❌ `以上就是今天的内容` · `希望对大家有帮助` · `总结一下`

发片时的标题、封面文案，直接从这里拿 —— 拿不出来的收尾，就是没提炼完。

## 五、候选法：一次写 5 个，挑 1 个

**这是整条链上最便宜的一步，也是「爆发点」唯一可控的来源。**

每个需要屏幕字的位置（每幕标题 / 每个素材点），先写 **5 个候选**，再从 5 个里挑 1 个：

| 角度 | 例（围绕"下沉市场"） |
|---|---|
| 数字型 | `54% 增量来自三四线` |
| 反差型 | `一线见顶，增量在下沉` |
| 代价型 | `下沉赚到了规模，赔掉了毛利` |
| 提问型 | `为什么越下沉越赚钱？` |
| 名词型 | `下沉市场的第三次机会` |

挑的顺序：**有刻度 > 可反驳 > 短 > 顺口**。

为什么必须写 5 个而不是 1 个：**第一个念头永远是最安全的那个**（也就是最平的）。
第 4、5 个候选才会出现反差结构 —— 爆发点就藏在那里。

> **落盘要求**：把这 5 个候选写进同名 `.md` 的「候选与选择」小节，并说明为什么选它。
> `.json` 里只放选中的那个（下游不需要看候选）。
> 这一小段是给人看的 —— 用户能一眼看出你是"挑"出来的还是"想"出来的。

## 六、对照表：平淡 → 提炼后

| 平淡 | 提炼后 | 差在哪 |
|---|---|---|
| 渠道问题 | 一线见顶，增量在下沉 | 从分类名变成判断 |
| 现状分析 | 54% 的增量来自三四线 | 从章节名变成数字 |
| 提升转化效果 | 转化率 1.8 倍，成本一半 | 补了刻度，删了口号 |
| 用户画像 | 25~34 岁占 6 成 | 从概念变成分布 |
| 内容概述 | 今年只做了三件事 | 从元话语变成事实 |
| 总结 | 往下走，才有增量 | 从流程词变成金句 |
| 我们要重视这个问题 | 这个问题的代价是复购 | 从呼吁变成代价 |
| 第一部分 | 一线为什么见顶 | 从占位符变成问题 |

规律只有一条：**把「关于什么的」换成「什么」**。

## 七、机器只能查到哪一步

`check-script.mjs` 第 7 项查的是**提炼度的下限**（`references/script-format.md` 不写这些，
它们属于"写法"而不是"字段"）：

| 判据 | 级别 | 为什么 |
|---|---|---|
| 空转标题（客套 / 结构占位 / 自我指涉） | **FAIL** | 100% 是没内容，`总结`、`第一部分`、`内容概述`、`今天我们来讲…` |
| 屏幕字重复 | **FAIL** | 同一句话说两遍，一定有一遍该删 |
| body 标题是纯名词短语 | **FAIL** | 连一个数字、一个判断词都没有，它就是话题不是结论 |
| 带数字的屏幕字 < 40% | note | 程度问题：全都带数字也会腻 |
| 开场标题没有钩子 | note | 前三秒最贵，但钩子形态有主观空间 |
| 收尾不像金句 | note | 金句没有唯一解 |
| 口号式标题（有形容词没数字） | note | 「赋能」「提升」不是错，没数字才是问题 |
| 素材点只有 1 个元素 | note | 缺关系层（见 `material-spec.md` 第一节） |

**过闸门 ≠ 提炼到位。** 这套规则的定位是挡住「明显的没做」——
真正的判据还是第一节那句：把屏幕字连起来读，像一段话还是像一份目录。

## 八、自检清单

- [ ] 屏幕字连起来读，像**一段论证**，不像目录
- [ ] 每条 body 标题**都能被反驳**（不是共识、不是分类名）
- [ ] ≥60% 的屏幕字带数字 / 对比 / 刻度
- [ ] 开场 3 秒内出现钩子，且不是「大家好」类台词
- [ ] 收尾那句话能**单独拿出去发**
- [ ] 每个位置都写了 **≥5 个候选**，并把候选与理由写进了 `.md`
- [ ] 遮住屏幕只听口播，逻辑不断（回到 `two-track-text.md` 第九节）
