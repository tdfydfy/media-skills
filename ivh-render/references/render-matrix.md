# 出片矩阵与故障排查

## 一、格式由产物决定，不由命令行决定

`render.mjs` 读产物 HTML 里的 `CONFIG.BG`，自己选编码。**不给你在命令行上选**——
因为选错了不会报错，只会安静地产出一份没法用的文件。

| `CONFIG.BG` | 编码 | 像素格式 | 容器 | 用途 |
|---|---|---|---|---|
| `transparent` | ProRes 4444（`prores_ks -profile:v 4444`） | `yuva444p10le` | `.mov` | 叠到实拍上 |
| `opaque` | H.264（`libx264 -crf 18`） | `yuv420p` | `.mp4` | 直接投放 / 投屏 |

> ProRes 4444 是行业默认的带 alpha 中间格式，剪映 / PR / FCP / DaVinci 都直读。
> 不要用 `.webm`（VP9 alpha）交付给剪辑软件——兼容性差得多。

## 二、抽帧密度：这是唯一的取舍点

这套链路**不是实时录屏**，而是「按秒定位 → 截图 → 串成序列 → 合成视频」。
每一帧都要按一次快门（默认引擎 0.10s/帧，回退引擎 1.1s/帧），所以帧数直接等于耗时。

| preset | `--step` | 采样帧率 | 30s 片子的帧数 | 适合 |
|---|---|---|---|---|
| `draft` | 0.1s | 10 fps | ~301 | 只用于用户明确要求的快速试片 |
| `normal`（默认） | 0.04s | 25 fps | ~751 | 默认。入场动效能看出过程 |
| `fine` | 1/30s | 30 fps | ~901 | 交付级。与输出帧率一一对应 |

**默认一把出 `normal`，出完就交。**

出片是分钟级的，**不要出两轮**：内容的对错在用户看 HTML 那一关已经确认过了，
再抽一轮 draft 只是把同样的时间花两遍。

> 这里说的是"不要重复出片"，不是"不要验收"。
> 验收发生在上一环——用户打开 HTML 看，看完点头，才轮到这一环。
> 渲染层不做画面判断（详见 SKILL.md 第二节）。

> **输出帧率 ≠ 采样密度。** 成片一律是恒定 30fps（`--fps` 可改）——容器负责保持帧，
> 剪辑软件拿到的始终是一条帧率正常的素材。但 `--fps` 造不出画面：
> 采样不足时中间帧就是重复的，文件会涨几十倍。要更流畅只能**降低 `--step`**（采更多真实帧）。
>
> 素材模式（透明 + 3:4）另有一层：出片时**空档帧只渲染一张、其余复用**，
> 渲染帧数与耗时都按复用后的值报（见 SKILL.md 第四节）。

## 三、两条抽帧引擎

| `--engine` | 机制 | 实测 | 前置条件 |
|---|---|---|---|
| `cdp`（默认） | 一个浏览器跑到底：逐帧 `IVH.seekAt(t)` + `Page.captureScreenshot` | 0.10s/帧 | 能连上 `127.0.0.1` 的调试端口 |
| `cli` | 每一帧拉起一次浏览器：`--screenshot=<path>` 落盘 / `--dump-dom` 读状态 | 1.1s/帧 | 无（全程零网络） |

`auto`（默认）先试 cdp，连不上调试端口（沙箱隔离子进程网络）就**自动**退回 cli ——
两条路的画面**逐像素一致**，回退只影响耗时。所以换机器、换沙箱都不会出不了片。

> 早先这里写的是「CDP 走不通，不要改回 CDP」。那是沙箱隔离网络时的结论；
> 现在 CDP 被自动探测 + 自动回退包住了，不再是一条硬约束。

实时录屏（screencast）仍然不用：它按真实时钟走，成片的时长与每帧的位置都不受控。

## 四、头号事故：假透明

`ffprobe` 报 `pix_fmt=yuva444p10le` **只说明有 alpha 平面，不说明平面里有内容**。
假 alpha（全 255）同样是 `yuva444p10le`，叠到视频上就是一块实心白板。

**唯一可信的判据是抽 alpha 平面看像素分布**，即 `check-alpha.mjs`。

根因只有一个：headless 浏览器默认给页面铺不透明白底。截图时必须传
`--default-background-color=00000000`（`shoot.mjs` 已内置，且在 `BG=transparent` 时才加）。

`render.mjs` 在透明产物出片后会**自动**跑一遍复检，不过就报错退出。
除非你明确知道自己跳过了什么，否则不要加 `--no-verify`。

**复检按时间点抽样，不解全片**（默认 12 点，`--samples N` 可调）。
这不是为了省事：alpha 平面转 rawvideo 是 1.48MB/帧（1080x1440），
一条 30s / 25fps 的素材是 **1.1GB** —— 塞进进程缓冲会直接爆，
然后被报成"取不到 alpha 平面"，看起来像"透明不合格"。
**安静误报比故障本身更贵**，所以宁可抽样。
抽样仍然会单独报出**最差的一帧**，闪一帧的假透明躲不掉。

## 五、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `前置检查` 报 `HIDE_HUD 不是 true` | 产物没设 `HIDE_HUD: true` | 改产物 CONFIG 后重跑。这是最快被肉眼发现的低级事故 |
| 前置检查报 `取不到总时长` | `timeline` 的 `data-out` 全是 0，或 `text` 的幕缺 `data-sec` | 补上时间；模板运行时会写 `data-duration` 但以内容为准 |
| 视频只有 1 帧 | 产物没有内容（`.comp` 或 `.scene`），或时间全为 0 | 检查时间轴 / 幕是否真的写了 |
| 成片里组件"闪一下就没" | `data-out - data-in` 太短，或抽帧跨过了整个停留期 | 降低 `--step`，或检查脚本里素材点停留是否 ≥0.8s |
| 找不到 ffmpeg | 未安装或不在 PATH | 设 `IVH_FFMPEG` 指向 `ffmpeg.exe` 全路径 |
| 找不到浏览器 | Edge / Chrome 装在非标准位置 | 设 `IVH_BROWSER` |
| 提示「空档帧实测不是全透明」而跳过了复用 | 空档里其实有东西：`HIDE_HUD` 没关、`BG` 不是 `transparent`、或 `.comp` 之外还有可见元素 | 先修产物；确认没问题再加 `--no-reuse-blank` 出片。别为了快把这道实测关掉 |
| 渲染比预期慢一个数量级 | 走了 cli 回退引擎（沙箱隔离子进程网络，连不上调试端口） | 正常现象，画面一致。耗时按 1.1s/帧 估 |
| 找不到调试端口 / 提示回退 | 沙箱隔离了子进程网络 | 不用处理，自动回退到 cli |
| 图片里数字永远是 0 | `?t=` 定位没有冻结计数器 | 产物模板的运行时已处理，不要改掉那段 |
| 数字截出 `+-1%` 这种脏值 | 计数器进度 `k` 没夹到 [0,1]，虚拟时间下 rAF 时间戳可早于采样点 | 模板已夹好，不要改回 `Math.min(1, ...)` |
| 文件比预期大 | 采样帧率远低于输出帧率，容器在大量重复帧 | 提高采样密度（调小 `--step`）；`--fps` 造不出画面 |
