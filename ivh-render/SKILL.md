# 渲染（信息图视频 · 第 4 环）

**只干一件事：HTML → 视频。不改内容、不改样式、不碰脚本。**

```
ivh-standalone ─┐
                ├─→ 产物.html ──→ [ 你在这里 ] ──→ .mp4 / .mov
ivh-overlay  ───┘
```

输出格式**由产物自己的 `CONFIG.BG` 决定**，不由命令行指定——
选错了不会报错，只会安静地产出一份没法用的文件。

---

## 一、跑一条命令就够

进来就是执行 —— 内容的对错在用户看 HTML 那一关（闸门 2）已经确认过了，
这里不再审核、不再等确认，跑完把产物路径给用户。

```bash
node scripts/render.mjs 产物.html
```

它按顺序做三件事：

1. **前置检查** —— 读产物 CONFIG，把「出片必然出错」的组合挡下来（未通过直接中止）
2. **抽帧 + 合成** —— 委托 `shoot.mjs`，透明走 ProRes 4444，不透明走 H.264
3. **透明复检** —— 透明产物自动跑 `check-alpha.mjs` 抽 alpha 平面，不合格就报错

常用选项：

```bash
node scripts/render.mjs 产物.html --preset draft     # 0.1s 一帧（采 10fps），快速看节奏
node scripts/render.mjs 产物.html --preset fine      # 1/30s 一帧（采 30fps），交付级
node scripts/render.mjs 产物.html --preflight        # 只检查，不渲染
node scripts/render.mjs 产物.html --out ./dist
node scripts/render.mjs 产物.html --scale 2          # 2 倍分辨率
node scripts/render.mjs 产物.html --engine cli       # 强制走逐帧浏览器（慢，零网络）
node scripts/render.mjs 产物.html --engine cdp       # 强制走单浏览器；两种传输都失败就报错退出
```

环境变量：`IVH_CDP_TRANSPORT=pipe|ws`（默认 auto：先管道、后 WebSocket）、`IVH_BROWSER`、`IVH_FFMPEG`。

## 二、三步里哪一步在判什么

出片是终点：**进来之前用户已经看过 HTML 并说没问题了**，"好不好看"在 ②③ 环就判完了。
`render.mjs` 里三个带"检查"字样的步骤，性质完全不同：

| 步骤 | 拍不拍图 | 成本 | 判什么 |
|---|---|---|---|
| ① 前置检查 | **不拍** —— 纯读 HTML 源码的正则 | 毫秒 | 出片必然失败的组合（时长算不出、透明没藏 HUD） |
| ② 抽帧合成 | **拍** —— 但这**就是出片本身** | 秒~分钟级 | 不判任何东西，产出的就是成品 |
| ③ 透明复检 | 读已产出的 `.mov`，抽 12 个时间点 | 秒级 | 文件能不能用（假 alpha 是头号事故） |

判一个步骤该不该留，看它判的是**文本 / 文件**还是**观感**：
前者交给机器（快、准、可重复），后者交给人（一次就够）。

## 三、前置检查会拦下什么

| 检查项 | 拦下原因 |
|---|---|
| 总时长必须 > 0 | `timeline` 取 `max(data-out)`；`text` 累加 `data-sec`。算不出来就没有帧序列 |
| `timeline` 必须有 `.comp` | 没有组件就没有时间序列 |
| `text` 必须有 `.scene` | 没有幕就没有内容 |
| `timeline` 的组件必须有 `data-in`/`data-out` | 缺了它们组件不会上场 |
| 透明产物必须 `HIDE_HUD: true` | 否则 `#hud` / `#kbd` / `#bar` 会被渲染进素材，底部留一条彩色进度条 |
| `ANIMATE` 建议为 `true` | 否则出片只有布局、没有动画（警告，不阻断） |

前三条任一不过，**中止出片**。这不是保守——它们是"产出了但没法用"的典型，
越晚发现越浪费。

> **两条排版路径都能出片。** `text`（分幕）同样是时间序列：模板把全局秒数换算成
> 「第 k 幕 + 幕内偏移」，用负 `animation-delay` + 暂停定格，抽帧走 `?t=`。
> 不带 `--step` 时才退回「每幕一张」的预览模式（走 `#<幕号>`）。

## 四、抽帧密度：唯一的取舍点

这套链路是「按秒定位 → 截图 → 串序列 → 合成」，**每多采一帧就多按一次快门**，
所以帧数直接等于耗时。两条抽帧引擎（`--engine auto|cdp|cli`，默认 auto）：

| 引擎 | 机制 | 实测 | 什么时候用 |
|---|---|---|---|
| `cdp` | 开一个浏览器，用 CDP 逐帧驱动产物的 `IVH.seekAt(t)` | **0.13s/帧** | 默认的快路径 |
| `cli` | 每帧拉起一个 headless 浏览器 + `--screenshot` 落盘 | 1.1s/帧 | 零网络、不依赖子进程回连 —— 回退路径 |

0.13s/帧 是 1920×1080 端到端实测（`seek` + 双 rAF 约 11ms，抓帧约 120ms），
其中抓帧的 91% 花在**浏览器内部的 PNG 编码**上 —— 所以提速旋钮在编码参数
（`optimizeForSpeed` 无损快压，默认已开，2.2 倍），在光栅化、落盘、管道上都找不到。

`cdp` 的传输自动择路：先试 **CDP 管道**（`--remote-debugging-pipe`，走子进程 fd3/fd4，
不经过 TCP），不成再试 **DevTools WebSocket**（127.0.0.1 回环）。
`IVH_CDP_TRANSPORT=pipe|ws` 可强制指定其中一种。

> 为什么默认管道：电脑管家 / 360 这类安全软件的网络防护会掐断**跨进程回环**，
> 症状是 `connect ETIMEDOUT 127.0.0.1:<端口>` —— `netstat` 里浏览器明明在 LISTENING，
> 同进程的 node 连自己也通，换任何进程去连就是超时。
> 管道整条链路都在父子进程的匿名管道里，不受影响（实测被拦的机器上仍是 0.13s/帧）。

`auto` 先试 cdp，两种传输都连不上才**自动**退回 cli。
**这条回退是硬要求** —— 换机器、换沙箱时不能变成"出不了片"；两条路的画面逐像素一致，
回退只损失时间。`--engine cli` 可强制走慢的那条。

### 并行抽帧（`--workers`）

默认切成「逻辑核 − 2」路，**两端封顶：≤8 逻辑核封 3，其余封 16**。每路一个独立进程 +
独立浏览器（`--workers N` 覆盖，`IVH_WORKERS` 同效；不足 8 帧/路时退回单路，
起进程的固定成本约 2s/路）。
**worker 只抓帧、不跑 ffmpeg** —— 编码只占出片总耗时 4%（93 帧/秒 vs 抽帧 8 帧/秒），
分 N 次编再 concat 只是多一处「参数必须完全一致」的风险。分片是捕获侧的工作单位。

**饱和点跟机器走，差得很远** —— 两个实测样本：

| 机器 | 路数 | 墙钟 | 提速 | 吞吐 |
|---|---|---|---|---|
| 笔记本 · 8 逻辑核 / 4 物理核<br>1920×1080 · 374 帧 | 1 | 51s | 1.00× | 7.3 帧/秒 |
| | 3 | 29s | **1.76×** | 12.9 帧/秒 |
| | 6 | 30s | 1.70× | 12.5 帧/秒（已饱和） |
| 台式 i5-14600K · 20 逻辑核 / 14 物理核<br>1080×1440 · 3072 帧实渲染 | 6 | 39.4s | 1.00× | 78 帧/秒 |
| | 10 | 28.1s | 1.40× | 109 帧/秒 |
| | 16 | 24.5s | **1.58×** | 123 帧/秒（仍在线性区） |

超线程对 zlib 几乎无效（PNG 编码要的是物理核）：4 物理核的笔记本 3 路就吃满了，
14 物理核的台式到 16 路还在涨。默认值按这个分档就是这个原因。**换机器要重标这两行。**

> **跨路数不是逐字节相同**（这条以前写错了）。台式上同一产物、同一帧集：6 路 vs 16 路有
> 90/4105 帧不同，单帧最多 1.57% 的通道值差 1~2 个色阶，PSNR 64 dB —— 肉眼是同一帧。
> 而 6 vs 6、16 vs 16 各自 4105/4105 **完全一致**。所以渲染是「**分片布局的确定性函数**」：
> **同一路数 100% 可复现**（空档复用、串行补抽、重跑都不受影响），跨路数只能算肉眼等价，
> 不能按 MD5 比。原因大概率是每个 worker 是独立浏览器会话，Chrome 的栅格化 / 图层提升
> 会随「这个会话已经渲了多少帧」演化，分片大小不同 → 会话历史不同 → 极少数帧取整差 1~2。

| preset | `--step` | 采样帧率 | 30s 片子 | 适合 |
|---|---|---|---|---|
| `draft` | 0.1s | 10 fps | ~301 帧 | 只用于用户明确要求的快速试片 |
| `normal`（默认） | 0.04s | 25 fps | ~751 帧 | 日常出片，入场动能看出过程 |
| `fine` | 1/30s | 30 fps | ~901 帧 | 交付级，与输出帧率一一对应 |

**默认一把出 `normal`，出完就交。** 出片是分钟级的，跑两轮就是双倍时间，
而内容的对错在用户看 HTML 那一关已经确认过了 —— `draft` 只在用户明确要求"先看个节奏"时才用。

> **输出帧率与采样密度是两件事。** 成片一律输出恒定 30fps（`--fps` 可改）：
> 采样不足的地方由容器保持帧，剪辑软件拿到的始终是一条 30fps 的正常素材。
> 但 `--fps` 不会凭空造出画面 —— 要更流畅只能**降低 `--step`**（采更多**真实**帧）。
>
> `--step` 是整数个帧周期时（`fine` 的 1/30、`draft` 的 0.1），采样点会精确落在帧栅格上：
> 第 k 个采样点就是第 k 帧，采样帧率与 `-r` 分毫不差。`normal` 的 0.04s = 1.2 帧，
> 落在格子之间，退回三位小数口径 —— 两头无法兼得。

### 素材模式自动跳过空档

透明素材（`PURPOSE=overlay` + `RATIO=3:4`）的时间轴大段是全透明的 ——
素材密度由内容决定。逐帧渲染那些空档等于白干：
实测同一份产物里两个空档时刻截出的 PNG **逐字节相同**（MD5 一致、alpha 平面全 0）。

于是出片时**只渲染「有内容的帧」+ 1 张空档帧，其余空档全部复用**：

| | 关掉复用（`--no-reuse-blank`） | 默认 |
|---|---|---|
| 渲染帧数 | 761 | 319 + 1（其余 442 帧硬链接复用） |
| 端到端耗时 | 89s | 43s |
| 成品 `.mov` | —— | **MD5 与改动前完全相同** |

（实测口径：`make-fixture.mjs` 的官方素材产物，30.4s / `normal` / 1080×1440 ProRes 4444。）

复用的前提是**空档帧真的全透明**，这一点会在渲染前**实测一次**
（`alphaextract` 抽 alpha 平面看是不是全 0），不是靠推断。不成立就自动退回均匀抽帧 ——
拿不准的时候宁可慢，也不要交一份画面不对的素材。`--no-reuse-blank` 可以关掉它。

## 五、出片产物

与 ivh-create 配合时，沿用作品目录并显式传 `--out <作品目录>/render`。独立调用未指定 --out 时，为兼容既有用法仍落在 `<产物同目录>/render-<名字>/`：

| 文件 | 说明 |
|---|---|
| `<名字>.mp4` / `<名字>-alpha.mov` | 成片。唯一要交出去的东西 |
| `.work/run-*/seq/` | 每次运行独立的 PNG 序列及 index.txt；其他临时帧也在同一 run 目录内 |

编码完成通过进程消息通知 render；若 shoot 在此后 5 秒仍未退出，render 终止残留进程并继续验收。透明产物先完成一次自动 alpha 抽检，再清理本轮临时目录；不做截图观感复审。清理在独立进程内执行，最多等待 15 秒，超时报告残留位置，不改变成片验收结果。编码或 alpha 检查失败时保留本轮临时文件；重试使用新目录，不等待旧目录清理。

要留在本地换编码参数重出一版（省掉几十分钟重抽帧），加 `--keep-frames`：

```bash
node scripts/render.mjs 产物.html --preset fine --keep-frames
```

## 六、透明：必须验到底层像素

`ffprobe` 报 `pix_fmt=yuva444p10le` **只说明有 alpha 平面，不说明平面里有内容**。
假 alpha（全 255）同样是 `yuva444p10le`，叠到实拍上就是一块实心白板。

**唯一可信判据是抽 alpha 平面看分布**（`check-alpha.mjs`）。`render.mjs` 已经自动跑它，
`--no-verify` 留给确有例外的场合。

`check-alpha.mjs` **按时间点抽样，不解全片**（默认 12 个点）：
alpha 平面转 rawvideo 是 1.48MB/帧（1080x1440），一条 30s 素材全解就是 1.1GB——
塞进进程缓冲直接爆，还会被误读成"透明不合格"。抽样后是秒级，判据一点没变，
而且会单独报出**最差的一帧**（整体达标但某一帧是实心，叠上去就是一闪的白板）。

```bash
node scripts/check-alpha.mjs 产物-alpha.mov --samples 20   # 想抽得更密
```

透明底是两条抽帧引擎各自的开关，都已内置：cli 是 `--default-background-color=00000000`，
cdp 是 `Emulation.setDefaultBackgroundColorOverride`。

## 七、文件

| 路径 | 用途 |
|---|---|
| `scripts/render.mjs` | **主入口**：前置检查 → 出片 → 透明复检 |
| `scripts/shoot.mjs` | 抽帧 / 逐幕截图 / 六风格对照 / `--video` 合成 |
| `scripts/cdp-shoot.mjs` | 单浏览器逐帧取样（快路径引擎；管道/WebSocket 两种传输，都不可用时返回 null，由 shoot.mjs 回退） |
| `scripts/active-windows.mjs` | 从产物源码算「哪些秒数上有内容」——空档复用与耗时估算共用这一份计划 |
| `scripts/shoot-at.mjs` | 定向复核：按组件入出点采样，核对卡点是否对齐 SRT |
| `scripts/check-alpha.mjs` | 抽 alpha 平面（按时间点抽样），判真透明 |
| `references/render-matrix.md` | 出片矩阵、抽帧取舍、故障排查表 |
| `../ivh-html-core/interop.md` | **产物契约**：渲染器靠哪些属性读数（共享层，唯一副本） |

## 八、边界

渲染层只出片，不判断也不修改：内容与画布尺寸由产物自报（`data-width` / `data-height`，
命令行只有 `--scale` 倍率），格式一切看 `CONFIG.BG`。
前置检查报的错，正确做法是回上游改产物。
