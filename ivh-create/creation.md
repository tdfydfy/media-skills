# 内容提炼与表达指引

内容策划阶段完整阅读；HTML 阶段按需回看“表达参考”和具体点的意图。两阶段共享这里的表达知识，视觉细节查选定风格的 spec.md。

## 创作目标

帮助观众看见口播中的重点、差异和关系，同时给原片保留注意力空间。先理解整段内容，再决定哪些地方值得出现素材。

重点可以是一项数字、一种变化、一个动作或一句值得记住的话。选择依据是画面能增加多少理解，不按句子数量分配卡片，也不强制章节、目录、眉题或每分钟的点数。

## 提炼时同时考虑画面

先判断这段信息要让观众注意什么，再选择可能的展示结构，最后压缩成适合阅读的屏幕字。展示方式可以反过来帮助发现缺少的比较对象、单位或动作，但不能补造事实。

压缩优先去掉重复、语气和连接词，保留会改变理解的对象、动作、数量、时间和条件。例如“客户明年 8 月结婚，没有替代方案”，仅剩“有风险”会丢掉真正有用的信息。

标题、关键词和正文各有用途。有的点一个词已经足够，有的点需要两侧信息；不要为了统一形式强行补齐每种文字层级。

## 表达参考

下面是常见思路，可以组合、变形或补充。名称供两阶段交流，不是需要校验的枚举，也不要求每个风格逐项实现。

| 内容关系 | 常用展示形式 | 提炼时保留什么 | 选择提示 |
|---|---|---|---|
| 一个关键量 | 大数字配一句解释 | 数值、单位、对象、必要口径 | 一个数值得记住时，通常不需要再加图表 |
| 对象比较 | 上下对照、双栏、并列数字、条形图 | 比较对象、共同维度、关键差异 | 区分观点对立与数值量差，历史值不自动等于错误值 |
| 状态变化 | 前后状态、箭头连接 | 起点、终点、变化方向 | 时间变化、因果、转移分别表达，箭头含义要明确 |
| 部分与整体 | 比例条、环图 | 整体、部分、比例或可计算的原始值 | 不同口径的百分比不能拼成一个整体 |
| 过程或步骤 | 编号节点、流程、逐项出现 | 动作、顺序、必要依赖 | 并列原因适合清单，执行顺序适合流程 |
| 多项并列 | 列表、分组卡片 | 每项的具体信息、分组依据 | 少量短项适合一屏；内容较长时分批呈现 |
| 概念或结论 | 关键词、词条解释、短引语 | 核心词、关键限定、需要时的解释或出处 | 单纯提醒与完整定义需要不同容量 |
| 时间走势 | 折线、阶段节点、方向示意 | 时间范围、趋势方向、已知数据 | 有数据才画数据曲线；只有方向就明确做示意 |
| 叙事位置 | 章节标记、简短提纲、回顾 | 真实内容结构、当前所处位置 | 结构较长、确实需要导航时再使用 |

选择形式时先看信息关系，再看风格擅长什么。第一阶段可以给出推荐形式与一句理由，不必决定 CSS 类名或内部元素数量。

## 节奏与时间

- 时间来自字幕或已对齐的音轨，记录原片绝对秒数。只有文稿时先策划内容，不把估算时间冒充对齐结果。
- 保留能回到原文的线索：字幕编号、时间范围或关键原句即可，无需复制整份字幕。
- 卡片的出现与对应信息同步。目录可提前提供结构；具体数值和结论避免早于口播揭示。
- 简单卡片停留 3～5 秒可以作为起点，复杂内容按阅读量调整；相邻点通常留出空档，让主体重新获得注意力。
- 根据内容安排密度、结尾与章节，不为填满时间轴补点。第一阶段给出的结束时间指画面完全离场，退场过程安排在该区间内。
- 没有看过原片时，不假设某个区域始终空闲，也不承诺无底文字在该处一定可读。

## 策划稿

默认只维护 `script.md` 一份内容来源。开头记录主题、源材料、风格和画幅；逐点写清时间、来源、屏幕内容、表达意图与展示建议。简单点可以合并叙述，不必重复填写空字段。

以下仅示范写法，不预设实际项目的内容或时长：

```markdown
# 反馈方式的变化

来源：interview.srt；风格：soft-relief；画幅：1080×1440。

## P01 · 18.6–23.2 秒

来源：字幕 8–9，“以前等月末开会，现在每天直接反馈”。
屏幕内容：以前｜月末开会；现在｜每日反馈。
意图：突出反馈频率发生变化，保留前后两种做法。
展示建议：上下对照，当前做法优先吸引注意。
```

写完后核对重点是否有来源、文字是否改变原意、数据口径是否完整、停留是否足够阅读。不同项目不必得到相同数量的点或相同的展示组合。
