# Neon Terminal · 霓虹终端

## 表达倾向

发光界面落在实拍画面上，通过明灭、亮条和接通顺序强调信息。适合数字、状态变化、对立关系与行动提示。内容策划时可参考下方组件形态，HTML 阶段再确定布局。

这套语言通过亮度区分焦点、次项和未激活状态。次项仍需清楚可读，较暗不自动表示缺席或错误。

## 保持风格的依据

- 正文以近白为主，荧光绿集中在线、状态和焦点上。大段绿字会降低可读性。
- 层级主要依靠亮度、发光强度与暗面板；维持清楚的视觉焦点。
- 数字和英文使用等宽字体，中文使用系统无衬线。
- 根据宿主画面选择暗底、亮条、括标或无壳。未见实拍时，优先用局部暗底保障可读性。

层级用三档表示，不用灰色：

| 档 | 形态 | 用在 |
|---|---|---|
| L2 亮 | 荧光绿 `1px` 边 + 外发光 + 深绿实底 | 焦点、结论、当前项 |
| L1 半亮 | 青 `1px` 边，不加发光 | 对照里的次项 |
| L0 灭 | 暗底 + `1px dashed` 边 + 次色字 | 缺席、旧状态、问题 |

同屏优先保留一个主要焦点；流程中的已激活节点可以同时点亮，用亮度和尺寸突出当前项。

边框只有 `1px` 和 `1px dashed` 两种。扫描线是面板材质不是内容，加在面板底上，不加在文字上：

```css
background-image: repeating-linear-gradient(180deg, rgba(57,255,106,.07) 0 1px, transparent 1px 4px);
```

四角括标（有底面板采用 `18px` 边、`2px` 粗，贴左上与右下）用来把面板读成一块屏；无底括标可成组放大到 36px / 3px。其他局部装饰见「零件」。

以下参数是统一起点，可为具体内容成组调整，保持层级关系：

| 项目 | 参考值 |
|---|---|
| 主强调 | `#39FF6A` |
| 正文 / 次文字 | `#EAFFF2` / `#7FA894` |
| 局部暗底 | `rgba(4,12,8,.82)`，需要时调整不透明度 |
| 次维度 / 警示 | `#2BE7FF` / `#FF3D8B`，按语义少量使用 |
| 字体 | 中文 PingFang SC / Microsoft YaHei；数字 ui-monospace / Consolas |
| 字号起点 | 核心数字 132～190px，标题 72px，词条 84px，正文 36px，标签 26px |
| 线与装饰 | 面板边线约 1px，重点亮条约 4px，角括标约 18px |
| 发光 | 模糊半径 10～18px、透明度约 .5，全片一致 |
| 配比上限 | 荧光绿 ≤15%，青 ≤8%，洋红 ≤3%，青与洋红不同时出现 |

```css
/* 有底面板参考 */
background: rgba(4,12,8,.82);
box-shadow: 0 0 0 1px #39FF6A,
            0 0 18px rgba(57,255,106,.5),
            inset 0 0 22px rgba(57,255,106,.10);

/* 无底文字的局部暗衬参考，仍需结合实际背景检查 */
text-shadow: 0 0 4px rgba(2,8,5,.95),
             0 3px 16px rgba(2,8,5,.92);
```

无壳与括标壳上的文字必须加三层暗描边，用于增强局部对比，仍需结合宿主画面确认可读性；绿光不代替暗衬：

```css
text-shadow: 0 0 4px rgba(2,8,5,.95),
             0 3px 16px rgba(2,8,5,.92),
             0 0 44px rgba(2,8,5,.72);
```

## 常用组件参考

| 组件形态 | 组织方式 | 容量 | 可调整的位置 |
|---|---|---|---|
| 终端数字 | 等宽大数字 + 上方标签 + 下方刻度条 | 归因 ≤12 字 | 是否有底、单位位置、重点亮度 |
| 占比 | 圆环：底环 L0、进度环 L2，环心放百分比 | 说明 ≤10 字 | 环粗细、起点方向、端点 |
| 数值比大小 | 每行：标签 + 水平柱 + 数值，柱长跟实际比例 | 标签 ≤8 字，2～4 行 | 条形、刻度条或环形；最大那行加端点 |
| 进度 | 刻度条逐格点亮 + 百分比 | 说明 ≤10 字 | 格数、方向、当前格 |
| 数字对比 | 两个巨字并列，一侧亮一侧灭 | 每侧 ≤8 字 | 左右或上下、亮的是哪侧 |
| 明灭对照 | 两组信息上下排列，以亮度突出当前重点 | 标签 ≤5 字，正文 ≤12 字 | 顺序与标签；较暗不自动代表错误 |
| 接通流程 | 节点之间用亮线连接，沿信息方向依次点亮 | 关系词 ≤8 字 | 节点数量、方向、时间顺序 |
| 三步递进 | 编号节点竖列，逐级点亮 | 每级 ≤8 字，2～3 级 | 编号形式、末级强调 |
| 终端列表 | 行首符号 + 短文本 + 行尾虚线 | 每行 ≤16 字，2～4 行 | 行数、分组、逐项出现 |
| 词条与释义 | 大词 + 打字机式释义，中间一根分隔线 | 词 ≤10 字，释义 ≤30 字 | 断行、是否需要提示符 |
| 关键词 | 一个巨词 + 一根长出来的亮条 | 词 ≤8 字（6 字起用 `.long`，字号降一档） | 位置、亮条长度 |
| 目录 | 竖排章节表：序号 + 标题 + 行尾虚线 | 标题 ≤10 字，2～6 条 | 是否给当前条、逐条点亮的节奏 |
| 章节标记 | 左上：空心大序号 + 亮条 + 标题 | 标题 ≤14 字 | 位置、序号样式 |
| 引语 | 方括号括标里的引文，落下方 | 正文 ≤34 字，署名 ≤16 字 | 括标大小、是否需要署名 |
| 趋势 | 折线图，暗网格 + 发光折线 | 说明 ≤14 字 | 位置、端点、是否带底 |

带底、折叠、亮条、括标、无壳都是可用的外观参考，按可读性和内容选择即可。不要求全片用齐，也不强制相邻两点换壳。

五档外观：

| 名称 | 长什么样 | 谁用 |
|---|---|---|
| 带底 | 半透明暗底 + `1px` 亮边 + 左上/右下四角括标 | 要压住实拍的内容：图表、多行清单 |
| 折叠 | 同带底，配合 FOLD-IN 沿中缝展开 | 表达展开或对立 |
| 亮条 | 只有左边一条 `4px` 亮条 + 半透明渐变底，无边框无括标 | 清单、进度、并列项 |
| 括标 | 无底，只有两只四角括标 | 标题、金句，实拍直接露出来 |
| 无壳 | 什么都没有，字自己发光 | 巨数字、词条 |

同一组件可切换外观，但应重新检查文字布局与宿主背景。按内容选择有底或无底，不规定全片配比，不为换壳破坏系列感。

需要补充上下文时，可在卡片上方加一行小标题（建议 ≤12 字）：短横先长出来，标签再滑进来，这是最像"信息卡"的动作。小标题写"这卡在讲什么"，内容写"具体是什么"，两者不重复；一块板只有一个。

目录、清单这类多行组件用三态：未讲（虚线边 + 次色字）、当前（L2 亮、行尾虚线在跑）、已讲（暗底、字压到次色、行尾停住）。同屏唯一的 L2 就是"当前"那一条。

## 动作

可用接通、描线、逐项点亮、折叠展开或轻微闪动帮助表达。常见入场约 400～800ms，退场约 220ms；阅读稳定性优先于动效数量。

持续感可以来自小光点、局部呼吸或沿线移动，避免整屏同时闪烁。扫描、电流等装饰控制在所属面板内，不覆盖正文。所有动态遵守生成指引中的时间定位接口。

可用的动效名与相位写法见「动效」一节，补足画面的小元素见「零件」一节。

## 零件

用来补足一块板，不单独成点。

| 零件 | 规格 | 用在哪 |
|---|---|---|
| 光点 | 8px 圆，荧光绿 + 12px 外发光；灭态改空心 8px 圈 | 端点、状态、行首 |
| 状态灯 | 10px 方，圆角 2px；亮 / 灭 / 洋红（坏） | 接通流程、状态变化 |
| 刻度 | 3px 竖条，间隔 26px，高 14px，次色；已点亮换荧光绿 | 大数字下方、进度 |
| 端点 | 折线或柱条末端 8px 圆，带 pulse | 轨道、趋势、比大小 |
| 角标 | L 形，`18px` 边 / `2px` 粗，荧光绿，贴面板左上与右下 | 有底面板 |
| 提示符 | `▸` 或 `›`，荧光绿，字重 700，永远在行首 | 清单、词条释义 |
| 单位角标 | 主数字的 28% 字号，次色，底对齐 | 终端数字 |
| 网格 | 折线图底：横 4 条 `1px` `rgba(127,168,148,.22)` 虚线 | 趋势 |
| 小标题 | 短横 44×2px + 等宽标签 23px（字距 .24em）+ 一根渐变线 | 需要上下文的卡片顶部 |
| 分隔线 | 一根从中缝往两边长出来的横线 | 词条与释义之间、段落之间 |
| 扫光 | 一道横向亮带自上而下走一遍后停住 | 有底面板，每个点只走一遍 |
| 电流束 | 一道竖直电流束横穿面板，循环 | 只放在 `overflow:hidden` 的壳上 |
| 电磁波 | 圆环从中心扩散到 3 倍后消失，循环 | 任何壳都能放；无壳的点做电磁波的主要手段 |

电流束放在无底壳上会漏到面板外，变成一条飘着的绿条，必须配 `overflow:hidden`。

## 动效

这套的"动"由电的接通与断开承担：灭 → 亮是入场，亮 → 灭是退场，亮着的时候也在动。

入场（写在卡片内元素的 `data-anim` 上）：

| 名字 | 手感 | 给谁 |
|---|---|---|
| POWER-IN | 闪一下再稳住，最通用 | 默认 |
| GLITCH-IN | 闪两下再稳住，横向轻抖 | 巨数字、大数字 |
| TRACE-IN | 面板先亮、内容从左被"画"出来 | 折线、圆环、流程 |
| BAR-IN | 柱 / 格 / 线从 0 长出来 | 柱条、进度、刻度 |
| STEP-IN | 逐行点亮，错峰约 140ms | 清单、目录、三步递进 |
| SLIDE-IN | 从右滑入，错峰约 110ms | 清单 |
| TYPE-IN | 逐字打出来，纯文本节点配 `data-type` / `data-dur` | 词条释义 |
| SLAM-IN | 从 1.4 倍砸下来 | 章节标记 |
| BLINK-IN | 慢一档闪两下 | 引语 |
| FOLD-IN | 沿中缝 `scaleY` 展开 | 折叠壳、表达对立 |
| SURGE-IN | 面板从左揭开，同时一道电流横穿 | 有底壳 |
| RISE-IN | 整块从下往上浮起 | 想稳一点的地方，配 `data-enter="none"` |

退场统一 FADE-OUT 240ms。这套语言里"消失"就是断电，不需要花样。

持续态（按表达需要选用；阅读阶段允许静止）：

| 名字 | 周期 | 手感 | 给谁 |
|---|---|---|---|
| pulse | 2.4s | 呼吸，透明度 1 → .45 → 1 | 光点、端点、状态灯、提示符 |
| breathe | 2.6s | 绿光涨落 | 对照里"亮"的那一行 |
| dash | 1.6s | 虚线相位向前跑 | 清单行尾、目录当前行 |
| flow | 2.2s | 一个光点沿线循环移动 | 接通流程的连线 |
| flick | 4s | 每 4s 微闪一次 | 章节序号 |
| scan | 3.6s | 一条扫光线自上而下走一遍后停 | 有底面板，每个点只走一遍 |
| beam | 3.4s | 电流束横穿一遍 | 有底壳 |
| ripple | 2.8s | 圆环扩散到 3 倍后消失 | 无壳的点 |

相邻点可复用同一种入场，同类内容优先保持系列感；需要强调变化时再轮换，不规定动效数量。

以下是默认配方，供选用和适配，不是逐项验收清单；展厅也可以演示其他组合：

| 组件 | 入场 | 持续态 |
|---|---|---|
| 终端数字 | GLITCH-IN + 数字跳涨（`data-to`） | 刻度条 pulse |
| 占比 | TRACE-IN + 环从 12 点顺时针长出来（`data-grow`） | 可选端点 pulse 或局部 ripple |
| 数值比大小 | BAR-IN，柱从 0 长，错峰 120ms | 最长那行的端点 pulse |
| 进度 | BAR-IN，格子逐格点亮 | 当前格 pulse |
| 数字对比 | GLITCH-IN，两侧同拍 | 亮的那侧 pulse |
| 明灭对照 | FOLD-IN | 灭的那行 dash、亮的那行 breathe |
| 接通流程 | STEP-IN 节点 + TRACE-IN 连线 | 连线上 flow |
| 三步递进 | STEP-IN 逐级，错峰 140ms | 末级节点 pulse |
| 终端列表 | SLIDE-IN 逐行，错峰 110ms | 行尾虚线 dash、行首光点 pulse |
| 词条与释义 | TYPE-IN + 词 GLITCH-IN | 提示符 pulse |
| 关键词 | POWER-IN，亮条同时长出来（`data-grow`） | 亮条 breathe |
| 目录 | STEP-IN 逐条，默认错峰 140ms，可调整 | 当前条 breathe、它的行尾 dash |
| 章节标记 | SLAM-IN | 序号 flick |
| 引语 | BLINK-IN，慢一档 | 可选括标 pulse，正文保持稳定 |
| 趋势 | TRACE-IN + 折线从左描出（形状固定，脚本不给数据点就不编点） | 末端端点 pulse |

需要变化时，可参考这些候选组：终端数字与数字对比轮 POWER-IN，数值比大小与进度轮 TRACE-IN，终端列表轮 STEP-IN，词条与释义轮 POWER-IN，接通流程轮 SURGE-IN，明灭对照轮 STEP-IN（上排先亮、下排再亮，可按内容调整错峰），关键词轮 GLITCH-IN。章节标记与引语只有一个候选，不轮换。

旧稿里的 `LOG-IN` 并入 `SLIDE-IN`，`WAVE-IN` 并入 `POWER-IN`，`SWITCH-IN` 的两排先后点亮由 `STEP-IN` 承担，`SPLIT-IN` 的两排对开由 `FOLD-IN` 承担，`GROW-IN` 由小标题自身的生长承担（短横先长、标签后滑）；`wave` 持续态不再使用。

相位由运行底座给出，CSS 一律写成暂停 + 负延迟，定格才会落在同一帧：

```css
.comp.in [data-anim="GLITCH-IN"]{animation:nt-glitch .42s var(--ease) both paused;animation-delay:calc(var(--hold,0s) * -1)}
.comp.in .pulse{animation:nt-pulse 2.4s linear infinite paused;animation-delay:calc(var(--hold,0s) * -1)}
.comp.out [data-anim]{animation:nt-fadeout .24s linear both paused;animation-delay:calc(var(--exit,0s) * -1)}
```

退场规则放在入场规则之后：两者权重相同，靠源顺序覆盖。

运行底座（`assets/base.html`）提供的能力，不写这些属性时行为与旧版一致：

| 写法 | 作用 |
|---|---|
| `.comp` 上加 `data-enter="none"` | 关掉默认的淡入上浮，入场完全交给 CSS（写 RISE-IN 这类整块动效时用） |
| 元素上写 `data-type`（纯文本） | 逐字显示，配 data-dur；换行仍按正常文本布局 |
| 元素上写 `data-anim="名字"` | 挂入场 / 退场关键帧；元素放在卡片内部，默认入场照旧叠加 |
| `data-to` 配 `data-prefix` / `data-suffix` / `data-dur` / `data-dec` / `data-group="1"` | 数字跳涨，值由当前时刻算出 |
| `data-grow="0~1"` | 生长量写进 `--grow`；带 `arc` 类的 SVG 圆改走 stroke-dash |

不要用 `setInterval`、`requestAnimationFrame` 或 CSS `transition` 承担入场：它们不认时间轴，定格会拍到中间值。浏览器打开同目录的 `showcase.html` 可以一次看完上面这些动效。
