# 口播叠加素材创作

一个技能完成内容策划与 HTML 制作两个阶段。先明确表达意图，再根据风格参考组织画面。默认制作 1080×1440 的透明叠加素材，原片承担声音和主体画面。

## 从当前进度继续

| 用户已有的材料 | 从哪里开始 | 阅读材料 |
|---|---|---|
| 视频、SRT 或文稿 | 内容策划 | [creation.md](creation.md)，以及选定风格的表达倾向和组件参考 |
| 已确认的策划稿 | HTML 制作 | 策划稿、[build.md](build.md)、选定风格的 spec.md；需要时回看 creation.md 的表达参考 |
| HTML 修改意见 | 修改当前产物 | 当前 HTML、相关策划内容与风格说明 |
| 已确认的 HTML，需要视频 | 交给渲染环节 | 同仓库的 [ivh-render](../../../ivh-render/SKILL.md) |

沿用用户已经给出的风格、内容选择与确认。风格未指定时，可结合内容推荐并说明选择；会实质影响方向时再询问。缺少可信时间码时可以先交内容策划，标明时间待对齐。

## 阶段审核与停止条件

默认分阶段交付，不在一轮里从策划直接做到视频：

| 当前阶段 | 完成后必须做什么 | 进入下一阶段的条件 |
|---|---|---|
| 内容策划 | 交付 `script.md` 的实际路径，说明等待脚本审核，然后结束当前轮次；不生成 HTML | 用户确认这份脚本或明确要求按此稿制作 HTML |
| HTML 制作 | 交付 `script.html` 和 `preview.html` 的实际路径，说明等待效果审核，然后结束当前轮次；不启动视频渲染 | 用户确认这版 HTML；若此前已要求出片，可继续渲染，否则等待出片请求 |
| 视频渲染 | 完成编码、透明复检和清理，交付视频 | 无后续默认阶段 |

“帮我生成视频”“完成这个作品”等整体目标不等于跳过阶段审核。只有用户明确要求“跳过审核”“不用等我确认，直接全部完成”等，才按指定范围连续执行。确认风格或方案不等于确认尚未生成的脚本或 HTML；文件已存在、检查通过、用户未回复也不算审核通过。

审核意见要求修改时，完成修改后重新交付当前阶段并等待确认，不把修改请求当成通过。用户明确说“按这些意见修改后直接做下一阶段”时按其指示执行。沿用对当前版本已给出的确认，不重复询问；脚本确认只放行 HTML 制作，不自动放行视频渲染。

## 两个创作阶段

### 内容策划

阅读 creation.md，结合风格的常见展示方式提炼内容。确定选点、屏幕文案、事实与关系、来源区间，并给出简短的展示建议。

默认交付一份 `script.md`，供用户确认表达内容。展示建议帮助下一阶段理解意图，不要求填写固定的组件类型、壳或字段数组。已有 JSON 或其他清晰的策划稿可以直接使用。

### HTML 制作

按 build.md 和风格说明生成 `script.html`。默认追求丰富且有节奏的视觉变化：先浏览选定风格的组件与动效索引，再统筹全片的布局、信息展开和主体动作。成熟组件是候选库，按内容选择和重组；现有组件确实不适合时，可以设计符合风格的新结构。具体选择方法见 build.md 的「整片视觉编排」。

保留已经确认的事实、核心文案、信息关系和时间。断行、层级与布局由本阶段决定；需要改变内容含义或时间安排时，明确指出涉及的点。

默认提供 HTML 和可双击的 `preview.html` 入口供用户确认效果，按上述停止条件结束当前轮次。具备已验证的 Hyperframes 适配时，可在效果审核阶段联合预览原视频和 HTML，详见 [build.md](build.md)。收到当前 HTML 的效果确认且已有出片请求后，调用 ivh-render。

## 输出位置与清单

每次执行都必须在输出根目录下直接新建一个按实际内容命名的作品文件夹，不得覆盖以前执行的任何文件。默认使用当前工作区的 `outputs/<内容名称>/`，例如 `outputs/反馈方式的变化/`；用户指定输出位置时，将其作为输出根目录。文件夹名称根据实际主题或作品名确定，已存在时依次追加 `-01`、`-02` 等序号，直到名称唯一，例如 `outputs/反馈方式的变化-01/`。不额外添加 `run-*` 或时间戳目录层。内部仍使用 `script.md`、`script.html`、`preview.html` 等固定文件名，通过不同作品文件夹隔离每次产物。开始时说明本次作品目录的绝对路径，同一次执行的各阶段都沿用它。技能的 `assets/`、`styles/` 和 `examples/` 不存放日常创作结果；只有明确收录样例时才写入 examples。

后续轮次的修改、续做下一阶段和重新渲染也算新的执行，仍在输出根目录下直接新建按内容命名的文件夹，不在历史作品目录内嵌套输出。仅检查或讨论已有结果、不写入产物时无需创建目录。续做时将旧产物作为读取输入，按需复制已确认的 `script.md`、`script.html` 和本地依赖，确保新目录中的预览与来源链接有效；原目录保持不变，不复制无关历史渲染或临时文件。

| 阶段 | 输出（相对本次作品目录） |
|---|---|
| 内容策划 | `script.md`，唯一策划明细；来源材料引用原路径或按需保存在本目录 |
| HTML 制作 | `script.html` 为唯一动画源文件；`preview.html` 为跳转到 `script.html?view=1` 的快捷入口，不复制动画内容 |
| 渲染 | `render/script-alpha.mov`（透明）或 `render/script.mp4`（不透明） |

调用渲染器时显式传 `--out <本次作品目录>/render`，重新渲染也不得指向历史输出目录。临时文件由渲染器放在 `render/.work/run-*/`，成功验收后清理；失败或指定保留帧时报告残留位置。只有排查实际问题或用户要求时才生成截图、检查日志，放在本次作品目录的 `checks/`。

交付回复直接列出本轮已完成文件的绝对路径、HTML 预览方式，以及未完成阶段或清理残留；不新增 delivery.md，不创建空目录或占位文件。

## 风格

- [soft-relief](../../styles/soft-relief/spec.md)：浅色承载板、柔影、凸凹层级，适合平稳解释与数据表达。
- [neon-terminal](../../styles/neon-terminal/spec.md)：暗面板、亮条、近白文字与荧光强调，适合变化、对立和重点提示。

MD 是 AI 的主要设计依据。HTML 范例用于看效果、参考实现与复用运行底座，需要时再读取。

## 创作边界

内容选择与表达方法见 creation.md，风格特征见各 spec.md，出片接口见 build.md。允许基于内容作设计判断，不要求穷举组件或证明每个决定符合分类表。

本技能与 ivh-render 作为同仓库的相邻目录使用。交付时给出产物路径，以及影响使用的未完成项或限制。
