# HTML 制作指引

输入是已确定的策划稿与风格。输出是可以预览、可以按时间定位并交给 ivh-render 的单文件 HTML。

## 阅读与设计

先读策划稿和选定风格的 spec.md；风格有模式分流时继续读取其 overlay 指引。浏览完整的组件参考和动效候选，避免只选熟悉的前几个。需要理解某种表达关系时，回看 [creation.md](creation.md) 的表达参考。有展厅索引时，按选中的候选定位 HTML 范例，读取相关结构、样式和动作实现，不要求通读所有组件代码。

以风格中的成熟组件作为候选库。内容基本适合时，调整尺寸、排列、行数、断行和呈现节奏；确实不适合时，沿用同一视觉语言设计新结构。

制作时保留策划稿的事实、核心文案、关系和时间。长文案先尝试重排与分步呈现，需要修改含义或延长时间再说明。临时新结构直接服务当前作品，反复有用时才考虑收录到风格参考。

## 整片视觉编排

默认追求丰富且有节奏的视觉变化。生成 HTML 前，按素材点的时间顺序统筹组件结构与布局、入场、信息展开顺序、主体动作和必要的持续态；这是本阶段内部设计，不新增交付文件、脚本字段或审核环节。

- 一个素材点有多个合适表达方式时，主动比较候选组合，再结合前后画面选择。差异优先来自布局、信息展开和主体动效，例如对照的两侧同步呈现或先后揭示、流程的节点接通、数字与对应图形共同增长；换颜色、换壳或增加闪烁只能作为补充。
- 连续重复同一套组件与动作时，判断是否确有系列表达需要；没有时，调整其中合适的点。回看全片是否始终是同一种清单、居中面板或整块淡入，避免每个点单独合理、连起来却雷同。
- 系列对照、章节导航等需要一致性的内容可保留共同结构，通过焦点转移、展开顺序与节奏体现变化。重点处可以更有力度，解释和长文阅读处留出稳定停留，避免所有点同时叠满效果。
- 变化受内容、可读性和已确认时间约束。没有定量依据就不制造百分比、比例条或趋势数据；并列项不改成因果或流程。短时段少做逐字、逐项铺陈，确保核心内容完整出现后仍有阅读时间。

不设组件数量、动效数量或换壳比例配额，也不要求用齐展厅。完成后按时间顺序检查实际采用的组合，调整无表达理由的重复；这项检查通过源码和时间安排完成，不增加逐点截图或预渲染流程。

## 风格与运行基础

风格由 MD 中的视觉原则、参数与组件参考约束。优先复用可用且经过验证的播放、定格和预览实现；视觉布局不必照搬整份模板。

将给人看的组件展厅与交付产物分开。正式 HTML 只包含本片内容及必要的预览功能，避免未使用的示例组件混入渲染时间轴。风格目录下的 `showcase.html` 就是给人看的展厅：看形态、看动效、抄实现时读它，不要整块搬进产物。

## 最小出片接口

以下约定用于对接现有 ivh-render。组件的内部结构、类名和入场方式由设计决定。

| 项目 | 约定 |
|---|---|
| 文件 | CSS、JavaScript、SVG 和必要资源内联；本地打开可工作，不依赖网络字体或 CDN |
| 默认画布 | 1080×1440，透明画布；承载板或面板只随相应内容出现 |
| 正式内容 | 放在 `#track` 内，每个定时内容组使用 `<div class="comp ...">` |
| 时间 | 在上述 div 写 `data-in="18.6" data-out="23.2"`，单位为原片绝对秒，有限数值且结束晚于开始 |
| 区间含义 | `data-in` 开始入场，`data-out` 时完全不可见；入场、停留、退场都在区间内完成 |
| 定格 | 暴露 `window.IVH.seekAt(t)`；直接跳到任意时刻可得正确状态，不依赖先前播放顺序或墙钟 |
| 预览 | `?view=1` 用于有底预览；`?t=秒` 用于定格；默认出片状态无背景、无 HUD、缩放为 1 |

底座另带一层可选效果层：入场关键帧、逐字显示、数字跳涨、生长量和持续态都由属性开启，属性名与相位写法见 `assets/base.html` 顶部注释。不写这些属性的内容与旧版逐字节一致，改底座不影响已有产物。这层与风格无关，具体动效名见所选风格的模式指引，例如 [neon-terminal overlay 的动效](../../styles/neon-terminal/overlay.md#动效)。

保留源码中的字面量 CONFIG，供当前渲染器读取。字符串使用单引号；HTML 属性使用双引号。STYLE 填实际风格目录名：

```javascript
const CONFIG = {
  PURPOSE: 'overlay',
  BASE: 'timeline',
  BG: 'transparent',
  RATIO: '3:4',
  STYLE: 'soft-relief',
  ANIMATE: true,
  HIDE_HUD: true
};
```

当前渲染器按正式组件最大的 `data-out` 决定素材结束时间，新产物将退场放在 end 之前，保持预览与出片一致。原片时长可以更长，素材无需为凑满原片增加内容。旧模板的退场语义可能不同，复用时核对。

数字和图形都应由当前时刻计算。装饰动画也要可以定格；持续动画按表达需要使用，不要求每个点永远运动。图表比例、方向、单位和显示数值保持一致。

## 预览与人工审核

默认在作品目录生成轻量的 `preview.html`，通过相对路径跳转到 `script.html?view=1`，并保留可点击链接作为跳转失败时的入口。动画、样式和播放逻辑统一维护在 `script.html`；渲染输入始终为 `script.html`，不使用预览入口或带预览参数的页面。

Hyperframes 可作为原视频与 HTML 的可选联合审核、剪辑工具，审核前无需先生成透明视频。当前 IVH HTML 尚未完成 Hyperframes 适配验证，不能直接宣称支持导入或剪辑，也不默认要求安装。普通作品继续使用上述本地预览入口。

接入时先验证原视频底层轨道与整体动效上层轨道的统一播放、拖动定位、裁剪后的时间映射、声音同步和保存后重新打开，再考虑逐组件编辑。原片绝对时间、剪辑后的时间和子动画局部时间需要明确转换；预览画布尺寸与叠加位置应符合实际成片。编辑结果必须供最终渲染读取，涉及内容或时间的变动应同步回策划稿，避免预览与交付使用不同版本。适配工程文件按需放在作品目录的 `hyperframes/`，未启用时不创建；不手工维护第二份动画源文件。

Hyperframes 接口以官方 [HTML 协议](https://hyperframes.heygen.com/reference/html-schema) 和 [组合时间约定](https://hyperframes.heygen.com/concepts/compositions) 为准。联合预览用于缩短审核等待，最终视频仍需渲染。

## 交付检查

核对策划稿中的文字、数字和时间是否落实；确认实际产物有内容、没有示例残留，文字没有溢出，默认打开不会把预览背景或控件带入素材。

日常创作由用户审阅 script.md 并通过 preview.html 直接播放 script.html 确认观感；已接入并验证 Hyperframes 的作品可联合审核原片与动效。不默认生成逐点截图、重复抽帧或先渲染一版再审核。只有用户指出具体问题、实际出现异常或修改时间引擎时，才针对相关时刻做必要的工程验证。

从仓库根目录运行只读前置检查：

```bash
node ivh-render/scripts/render.mjs path/to/script.html --preflight
```

前置检查通过说明源码满足渲染器的部分条件，不等于人工审核通过。交付 `script.html` 和 `preview.html` 的实际路径，说明预览方式、尚未验证的事项及“等待 HTML 效果审核，确认后渲染”，然后结束当前轮次，不启动渲染。修改后重新交付审核；阶段跳过仅按 [workflow.md](workflow.md) 中用户明确指示的例外处理。

输出位置和清单沿用 [workflow.md](workflow.md) 的作品目录约定，每次执行在输出根目录下直接新建按内容命名的文件夹。用户确认效果且已要求出片时，按 [ivh-render](../../../ivh-render/SKILL.md) 执行。现有渲染器默认将透明素材输出为 ProRes 4444 MOV；其他格式按实际支持情况处理。
