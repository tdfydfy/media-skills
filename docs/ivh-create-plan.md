# ivh-create 开发计划

更新日期：2026-09-17。

## 目标与当前状态

在当前仓库新增 `ivh-create`：一个技能串联内容策划与 HTML 制作，复用独立的 `ivh-render` 出片。让模型依据表达知识与成熟组件作设计判断，减少固定类型、字段映射和多份规范同步。

本次已完成技能入口、合并的创作指引、生成指引、两个风格 MD、无依赖 HTML 运行底座，以及一个从真实 SRT 制作的 `neon-terminal` 完整样例。样例已通过时间轴、透明画布、代表帧、桌面/窄屏预览、实际渲染和 alpha 检查。仓库根 README 已切换到新主线；仅仓库内的技能入口已创建，尚未安装到个人技能目录。

`ivh-next` 作为现有参考保留；本次不修改其已有工作区内容，也不改动渲染器。后续根据本计划在新技能中逐步落地。

## 已确定的设计

| 决策 | 目的 |
|---|---|
| 一个入口、两个阶段 | 连续保留创作意图，分别确认内容与效果；已授权连续完成时直接继续 |
| 提炼与表达合并为 creation.md | 第一阶段带着展示意识策划，第二阶段共享同一份表达知识 |
| 默认策划稿为 script.md | 减少 JSON、阅读稿和 HTML 三份内容同步；已有结构化稿仍可接收 |
| 组件是默认起点，允许适配 | 保留风格稳定性，让模型调整布局、容量与节奏 |
| 风格以 MD 为主要依据 | 保留具体参数与典型组件，HTML 按需用于展示和参考实现 |
| 通用指引不收录具体风格画法 | 新风格主要增加自己的说明，不扩展所有风格的类型映射表 |
| 运行基础少而稳定 | 可靠定格、透明画布、时间与渲染接口保留明确约定 |
| 自动检查聚焦可用性 | 不用组件枚举、强制密度、壳或动效计数代替设计判断 |

文件名使用英文，正文使用中文。开发计划留在 `docs/`，不要求模型每次创作读取项目开发历史。

## 阶段 2：用内容样例校准第一阶段

工作：选用一段有来源的短口播和一段较长解释内容，按 creation.md 产出策划稿；先确定需要保留的信息，再看展示建议是否帮助提炼。

产物：少量 `source.srt` / `script.md` 示例，放在 `examples/` 的独立案例目录。新增素材使用可公开的材料或明确标注的合成内容。

验收：短内容能自然省略目录，长内容能组织关系；来源、事实与口径可核对；另一轮对话只凭原始材料、策划稿和技能文件即可继续，无需恢复完整聊天记录。

只有使用中反复暴露的问题才补充指引，不为每种输入写一套特殊流程。

完成记录：已用 `C:\Users\mydfy\Videos\9月16日 - 2.srt` 制作 `examples/bilibili-levels/source.srt` 与 `script.md`。策划稿保留了来源中的事实不确定性，并将升级路径、耗时对比、玩笑段和付费说法组织为 15 个时间卡片；可以只凭素材、策划稿和技能文件继续第二阶段。

## 阶段 3：准备最小运行底座与风格展示

工作：从现有实现中复用时间定位、透明画布和必要预览能力，整理为 `assets/base.html`；正式素材与风格展厅分开。模型使用 MD 做设计，在底座上写本片内容。

本阶段需要明确的少量工程约定：

- 新产物的 end / data-out 表示完全离场，退场安排在区间内；预览和渲染器取相同的素材时长。
- 任意时刻可以直接定格，数字、图形与装饰动画不依赖前一次播放状态。
- 默认打开是透明出片状态，预览背景与控件只在预览模式出现。
- 正式文件只保留真实内容，避免当前渲染器把展厅组件计入时间轴。

迁移时修复所复用实现中会影响当前产物的缺陷，例如默认退场未触发、图形指示与数值不同步；不扩展成全仓库历史问题修复。

验收：在入场、中段、退场和空档可正确定位；换内容时不需要重写时间引擎；产物保持单文件，不增加依赖安装步骤。

完成记录：`assets/base.html` 已实现 `window.IVH.seekAt(t)`、`data-in` / `data-out`、元素级 `data-reveal`、透明默认画布和 `?view=1` 预览。`bilibili-levels/script.html` 已通过 `ivh-render` 前置检查、15 个卡片的时间结构检查、60 张代表帧检查，以及 1280px 桌面和 500px 窄视口预览检查。

## 阶段 4：按实际需求扩展风格与表达

工作：从已确认的策划稿制作 HTML，覆盖成熟组件直接使用和按内容适配两类情况。按实际作品需求补充风格样例或 showcase.html，不以“每个风格必须先有完整案例”为前置条件。

当前进度：`neon-terminal` 已有 `bilibili-levels/script.html` 完整案例。`soft-relief` 说明保留，待确有合适内容和使用需求时再制作案例。

验收：同一表达意图可在两种风格下成立；文字较长或条目较多时可合理适配；不要求固定 kind/form、所有壳全用齐或每个点持续运动。风格一致性由画面判断。

扩展性检查：新增或补强风格时，先用小规模设计试验确认只需调整风格说明和必要参考即可使用，不必修改共同表达类型清单或新增一套字段映射。

## 阶段 5：接入渲染并整理使用入口

工作：对代表性产物运行现有前置检查和实际渲染，核对时长、透明通道与末尾退场。确认新流程可用后，更新仓库根 README 的主入口，说明新旧目录用途。

验收：至少一份真实通过渲染和 alpha 检查的透明素材；用户仅凭技能入口即可走完内容策划、HTML 制作和出片。文档中清楚区分已经测试的能力与未来设想。

默认沿用现有工具。只有真实使用证明某项重复检查值得自动化，才增加小脚本；不迁移旧 check.mjs 的整个类型和风格映射体系。

完成记录：`examples/bilibili-levels/script.html` 已在 2026-09-17 通过 `normal` 预设实际渲染。产物为 `render-script/script-alpha.mov`，1080×1440、30fps、183.57 秒、ProRes 4444（`yuva444p12le`），文件约 1.60GB。渲染器抽取 12 帧检查 alpha 平面，完全透明像素平均占 73.66%，最差一帧为 45.23%，确认透明通道有效。仓库根 README 已将 `ivh-create → ivh-render` 设为主入口，并将 `ivh-next` 标为旧版参考。
