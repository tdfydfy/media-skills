柔面凸凹

整幅画面只有一个颜色，靠左上白影与右下灰影把东西托起来

01定位与适用

整个画面只有一个颜色。所有东西靠同一道光源的两侧柔影，从底色上被"托起来"或"压下去"。

softtactilequiet

适用说明
概念解释一个论点配一件物证。元素少、需要安静与手感
产品演示模拟真实器物的凸凹，观者能一眼"看出怎么按"
教程步骤步骤之间靠凸 / 凹区分当前项，不需要额外标记

现有五套都靠一张照片提供氛围，这一套不依赖任何图像——画面本身就是一件物件。元素超过 12 个、或需要强对比排序时，改用高对比的语言：本套的明度空间不足以承担密集排布。

03形状语汇

唯一基本形是圆角矩形。圆角 = 短边 × 0.28，夹在 16–40 之间。

04层次与边缘

光源恒定在左上 315°，永不改变。凸起用外影，凹陷用内影，两者互为反向。

凸起 out
box-shadow: -6px -6px 12px rgba(255,255,255,.92),
             6px  6px 14px rgba(163,177,198,.55);

凹陷 in
box-shadow: inset -5px -5px 10px rgba(255,255,255,.92),
            inset  5px  5px 12px rgba(163,177,198,.50);
级形态用于
L0 贴底无影画布本身
L1 微凸外影 6 / 6元素默认态
L2 抬起外影 10 / 10 + 上移 2px悬停、当前项
L3 凹陷内影 5 / 5输入位、轨道、选中
L4 焦点实心强调色块 ≤3%全屏唯一

语言边界：本套的层次只由双向柔影承担。描边线、明度面分层、模糊材质、硬投影都不参与构图。

08表面与材质

表面是均质的磨砂塑料，质感全部由柔影的模糊半径承担。

纹理零。无颗粒、无网点、无纸纹、无渐变
模糊半径10–14px，是"软"的唯一来源；低于 8px 会退化成硬投影
理由这套的"真"来自几何精确 + 影的柔和，任何纹理都会让它读起来像表面脏了

12·A透明载体的承载板

透明底没有桌面。必须由产物自己画一块承载板，柔影才有落点；板以外保持全透明。

项值说明
板色#E4E9F0与元素填充色必须同一值，否则凸起失效（实测见下）
不透明度实心（首选）或 ≥0.96实测 α=0.94 时画面的细纹理已经可见
边缘实心板 + 40px 羽化硬边会被读成「贴上去的卡片」；羽化后读作软窗口
磨砂不可用透明模式下页面里没有画面可虚化，模板已写死 backdrop-filter:none
深色变体板 #2B3238
亮影 rgba(255,255,255,.07) 暗影 rgba(0,0,0,.55)		叠在亮实拍上对比更强，是本套在透明支线的推荐方向

三条实测结论（同一块画面、只变板参数）：
① 板若用纯白——左上白影落在白底上直接消失，凸起退化成普通投影；且板上元素比板更暗，「同色」前提被破坏。凹陷反而幸存，因为它的亮影是内影、自带底色。所以「同色」是硬前提，不是审美偏好。
② 实心板 + 40px 羽化——内部零漏液，保住第 08 节的「零纹理」；边缘是软过渡而不是硬切口。
③ 半透明承载板漏进来的画面纹理，与模板里那条「透明底没有『纸』，纹理必须全关，否则导出后变成浮动脏条纹」是同一件事。所以不透明度要么给足，要么干脆实心。

板与板之间留 ≥1.5s 纯透明，同一时刻只有一块板——这条来自透明支线的时间轴规则，不在这套里重定义。

项值理由

分隔件裁决—
别家怎么分border-top / 发丝线 / 虚线（minimal、blueprint 都这么做）

① c-line 折线没有体积，凸凹语汇完全用不上。明说：线只靠 --ink（2.5px 粗）与数据点（8px 凹陷小孔）区分，不参与凸凹。

15·A专属动效

既有 13 种入场没有一种适合本套——它们全是位移、擦出、缩放、模糊，没有一种是「从表面顶出来」。必须新增两种。这套把 .comp 本身当作板（背景 #E4E9F0 + 双影 + 圆角 24px），组件只负责排版；所以 keyframes 直接作用在 .comp 上即可，不用给每个组件各写一套。

@keyframes embossin{                    /* 由凹到凸：内影退出、外影顶出 */
  0%  {opacity:0; transform:scale(.965);
       box-shadow:inset -4px -4px 9px rgba(255,255,255,.92),
                  inset  4px  4px 10px rgba(163,177,198,.50);}
  38% {opacity:1;}
  100%{opacity:1; transform:scale(1);
       box-shadow:-6px -6px 12px rgba(255,255,255,.92),
                   6px  6px 14px rgba(163,177,198,.55);}
}
@keyframes sinkout{                     /* 压回凹陷 */
  0%  {opacity:1; transform:scale(1);
       box-shadow:-6px -6px 12px rgba(255,255,255,.92),
                   6px  6px 14px rgba(163,177,198,.55);}
  100%{opacity:0; transform:scale(.972);
       box-shadow:inset -4px -4px 9px rgba(255,255,255,.92),
                  inset  4px  4px 10px rgba(163,177,198,.50);}
}
前置动作—
注册入场body.animate .comp.in[data-anim="EMBOSS-IN"]{animation:embossin .36s cubic-bezier(.34,1.32,.64,1) both}
注册退场body.animate .comp.out[data-out-anim="SINK-OUT"]{animation:sinkout .24s ease-in both}
为什么必须先注册入场映射是逐字匹配的。名字不认识时不会报错——那块板只是不动，而「用了 ≥3 种入场」这一条照样判通过。校验器抓不到，只能靠人记
语言边界（动效）—
本套只用这三种EMBOSS-IN（凸起件）/ SCALE-POP（数字件，模板已有）/ FADE-IN（凹陷件，模板已有）
不用其余 12 种位移、擦出、模糊、跳帧都会把「同一块表面」的错觉打散
只注册 EMBOSS-IN 就够另两种模板里已有，刚好凑满 ≥3 种入场的硬线
keyframes 数量embossin / sinkout / scalepop / fadein / fadeout = 5 种，满足模板 ≥4 的要求

过渡实现：给元素两层伪元素分别承载内影与外影，用透明度交叉过渡，比直接动画 box-shadow 流畅得多。

16在场演化

前十五节管的是「一块板长什么样、怎么出现」。只做到这一步，一块板停 5 秒就有 4 秒是死帧——信息本身还没动。数字该从 0 涨上来、条该从槽里挤出来、大和小该被演成一次对比，这些是「论点在动」，不是「装饰在动」。这一节把它们定下来。

16·A数字跳涨

先记一条硬事实：模板自带的 .num 计数器在这条流水线里是废的。它走 requestAnimationFrame，而渲染器每取一帧都会调 IVH.seekAt()，里面那句 freezeCounters() 会把数字直接写成终值。成片里从第一帧到最后一帧都是终值——「跳涨」这个动作根本进不了帧。
所以任何会变的数字都必须做成 CSS 动画。把整数注册成可插值属性、用 counter() 渲染成文本，整条链就都在 CSS 里，负 animation-delay + paused 便能定格在「第几跳」上。

@property --nv  {syntax:"<integer>"; initial-value:0; inherits:false}
@property --nto {syntax:"<integer>"; initial-value:0; inherits:false}

@keyframes numcount{ from{--nv:0} to{--nv:var(--nto)} }

.num-up{
  counter-reset:nv var(--nv);
  animation:numcount 1.05s cubic-bezier(.22,.9,.28,1) both;
  animation-delay:.34s;                  /* 等板先顶出来，再开始跳 */
}
.num-up::after{content:counter(nv)}      /* 元素内留空，文本全由 counter 出 */
.num-up[data-tick]{animation-timing-function:steps(12,end)}   /* 逐格跳的手感 */

用的时候只写 <span class="num-up" style="--nto:78"></span>——目标值是内联的，keyframes 全局只写一次。

四个坑为什么
元素内不能放文本::after 把 counter 追加在原文之后：元素里写「78」会渲染成「780」
只能整数counter() 不接受小数。要小数就拆成整数位与小数位两段分开跳
animation-delay 写在简写之后animation 简写会把 delay 重置为 0，写在它前面等于没写
数字牌要跟着跳一下只有数字变、牌不动，会像贴纸。本套的做法是每跳一拍把柔影从「凸」顶到「更凸」（numkick）——用影的深浅表现重量，不用位移

16·B柱条生长

模板给 .c-bar .fill 挂的是 grow（scaleY 纵向生长）。对一条 18px 高的填充条来说，纵向生长看着只是「变粗」，跟长度没关系。本套要的是横向挤出，而且过程中柔影要由内凹翻成外凸——所以它不是「变长」，是「从凹陷里被顶出来的实体」。

@keyframes bargrow{
  0%  {width:0%; opacity:0;
       box-shadow:inset -3px -3px 6px rgba(255,255,255,.90),
                  inset  3px  3px 7px rgba(163,177,198,.50);}
  14% {opacity:1;}
  56% {box-shadow:inset -1px -1px 3px rgba(255,255,255,.90),
                  inset  1px  1px 3px rgba(163,177,198,.45);}
  100%{width:var(--w); opacity:1;
       box-shadow:-3px -3px 7px rgba(255,255,255,.95),
                   3px  3px 8px rgba(163,177,198,.60);}
}
要点—
宽度走 --w，不读内联 width关键帧的终值要能引用元素自己的值：<div class="fill" style="--w:78%">，基础规则写 width:var(--w,50%)
错开 0.16s / 行每行只写自己的 animation-delay，定格机制本来就逐个子元素读 delay
数字晚于条 0.5s条先挤出、数字随后到，观众的眼睛才有落点

16·C大小对比

「比较」不是把两个数并排放好，而是让它们演一次音量差：起手时大的还是凹的、小的还是凸的，收尾时各自归位。中间那一拍反转，才叫对比。

@keyframes bigup{                        /* 大的：从沉的顶上来 */
  0%  {transform:scale(.84); box-shadow:var(--n-in-sm)}
  62% {transform:scale(1.045)}
  100%{transform:scale(1);   box-shadow:var(--n-out)}
}
@keyframes smalldown{                    /* 小的：从凸的沉下去 */
  0%  {transform:scale(1.20); box-shadow:var(--n-out)}
  100%{transform:scale(.90);  box-shadow:var(--n-in-sm)}
}

两者 delay 相差 0.16s，小的先沉、大的后顶。组件用 c-cmp，但要覆写掉它的 border 与 text-decoration:line-through——两者都违反本套（§03 零形变、§04 禁描边线），中缝的 .vs 直接不显示，分隔交给间距。

16·D循环与边界

另外两个配套动作，写法和上面同构：

@keyframes pressin{                     /* 清单行：从更深地压进底面回到正常凹陷 */
  0%  {opacity:0; transform:translateY(-7px);
       box-shadow:inset -7px -7px 14px rgba(255,255,255,.95),
                  inset  7px  7px 15px rgba(163,177,198,.62);}
  100%{opacity:1; transform:none; box-shadow:var(--n-in-sm);}
}
@keyframes breathe{                     /* 柔影呼吸：0%/100% 必须等于该元素的基础态 */
  0%,100%{box-shadow:var(--n-in)}
  50%    {box-shadow:inset -6px -6px 13px rgba(255,255,255,.94),
                     inset  6px  6px 15px rgba(163,177,198,.58);}
}
动作用在哪什么时候别用
数字跳涨 NUM-UP单个指标当论点，停留 ≥2s一屏三个以上数字同时跳（互相打架）；数字本身不是论点时
柱条生长 BAR-GROW占比、构成、同一口径的几条对比数值差小于 5%——长度差看不出来，改用数字跳涨
大小对比 SCALE-CMP两件事的音量差三件以上（对比退化成排队）；两块尺寸本来就相等时
行压入 PRESS-IN清单、步骤、逐条给行数超过 5 行——最后一行要等到 0.7s 之后
柔影呼吸 BREATHE全片只给一个元素，表示「它活着」板上出现第二个；幅度超过 25%（会变成发光）
本套的额外约束—
不用位移表达弹性本套的「动」由影的深浅与形状的进出承担。位移只保留 7px 这一个量级（行压入），再多就变成别的风格了
数字牌必须跟着跳只有数字变、牌不动会像贴纸。每跳一拍把柔影从「凸」顶到「更凸」——用影的深浅表现重量
呼吸全片只留一处板上出现第二个不同步的呼吸，会读成「界面坏了」。这也是本套唯一的循环动效
动作数 < 幕数一屏里同时演出的动作不超过两个。三个以上会互相抢注意力，而本套的说服力恰恰来自克制

公共层那三条硬规定——一个元素只挂一个动画、循环动效首尾帧等于基础态、新动画名逐字注册——本套同样适用，写法与实测见 design-specs/motion-spec.md §1.3 与 §2④，此处不重复。
