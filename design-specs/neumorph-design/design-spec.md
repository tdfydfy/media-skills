# 柔面凸凹 · Soft Relief

> 设计规范摘要 · 可直接整段粘贴进 prompt

**一句话**：整个画面只有一个颜色。所有东西靠同一道光源的两侧柔影，从底色上被"托起来"或"压下去"。

关键词：soft / tactile / quiet。适用概念解释、产品演示、教程步骤；元素少、要安静与手感。
不依赖任何照片——**画面本身就是一件物件**。

---

## 01 定位与适用

| 适用 | 说明 |
|---|---|
| 概念解释 | 一个论点配一件物证 |
| 产品演示 | 模拟真实器物凸凹，观者一眼看出怎么按 |
| 教程步骤 | 靠凸 / 凹区分当前项，不需要额外标记 |

元素 > 12 个，或需要强对比排序时，改用高对比的语言。

## 02 画布与尺度

| 项 | 值 |
|---|---|
| 画布色 | `#E4E9F0`（唯一底色，浅冷灰蓝） |
| 安全区 | 四周 8%（1920×1080 约 86px） |
| 主元素占屏 | 宽 52–68%，高 40–60% |
| 元素间距 | 24 / 32 / 48（只用这三档） |
| 卡片内边距 | 32 / 40 |
| 留白占比 | ≥ 35% |

## 03 形状语汇

- 唯一基本形：**圆角矩形**。圆角 = 短边 × 0.28，夹在 **16–40** 之间。
- 三档：`16` 按钮与凹槽 / `28` 卡片 / `40` 大容器。
- 圆形只用于头像位与状态点，不作装饰。
- **形变 = 0**：不抖、不斜、不手绘。
- 第三种态：同一个矩形把柔影反向即为**凹陷**。

## 04 层次与边缘

光源恒定 **左上 315°**，永不改变。凸起用外影，凹陷用内影。

```css
/* 凸起 */
box-shadow: -6px -6px 12px rgba(255,255,255,.92),
             6px  6px 14px rgba(163,177,198,.55);

/* 凹陷 */
box-shadow: inset -5px -5px 10px rgba(255,255,255,.92),
            inset  5px  5px 12px rgba(163,177,198,.50);
```

| 级 | 形态 | 用于 |
|---|---|---|
| L0 贴底 | 无影 | 画布本身 |
| L1 微凸 | 外影 6 / 6 | 元素默认态 |
| L2 抬起 | 外影 10 / 10 + 上移 2px | 悬停、当前项 |
| L3 凹陷 | 内影 5 / 5 | 输入位、轨道、选中 |
| L4 焦点 | 实心强调色块 ≤3% | 全屏唯一 |

**语言边界**：层次只由双向柔影承担。描边线、明度面分层、模糊材质、硬投影都不参与构图。

## 05 色彩系统

| 名 | 值 | 角色 |
|---|---|---|
| 画布 | `#E4E9F0` | 底色，78% |
| 亮影白 | `#FFFFFF` | 材质，光源侧 |
| 暗影灰 | `#A3B1C6` | 材质，背光侧 |
| 主文字 | `#3D4A5C` | 主张与数字 |
| 次文字 | `#6B7A90` | 说明与单位 |
| 弱文字 | `#97A3B5` | 标签与序号（仅 ≥24px） |
| 强调红 | `#E8555A` | 唯一焦点，≤3%，一屏一处 |
| 对照蓝 | `#4A90D9` | 对照项，≤8% |

- **明度序：越深越重要**（浅底逻辑），最深一档给结论。
- 正文 ≥ `#6B7A90`；`#97A3B5` 只用于 ≥24px 标签。
- 亮影白与暗影灰是**材质**不是颜色，不参与配色计算。

## 06 字体系统

无衬线（Inter / SF Pro / 系统栈）。**字重只用 500 和 700**。

| 用途 | 字号 | 字重 | 字距 |
|---|---|---|---|
| 主张 | 96 | 700 | −2% |
| 标题 | 64 | 700 | −2% |
| 小标题 | 40 | 500 | −1% |
| 正文 | 28 | 500 | 0 |
| 说明 | 20 | 500 | 0 |
| 标签 | 16 | 500 | +14% |

字号为 1920×1080 基准。行高：大标题 1.1，正文 1.6。

## 07 版式骨架

| 骨架 | 结构 | 用于 |
|---|---|---|
| 单件式 | 一个大凸起居中偏上 | 单一概念 |
| 托盘式 | 凹陷大盘托住 2–3 个凸起小块 | 并列与对比 |
| 侧列式 | 左 38% 文字 + 右 62% 物件 | 说明型 |

- 视觉重心落在垂直 **42%** 处（物件摆在桌上，不是贴在墙中央）。
- 一屏凸起 ≤3 个、凹陷 ≤5 个。
- 宁可不对齐也不压间距，元素之间 ≥24px。

## 08 表面与材质

- 表面是**均质的磨砂塑料**，质感全部由柔影的模糊半径承担。
- 模糊半径 **10–14px**，是"软"的唯一来源；低于 8px 会退化成硬投影。
- **零纹理**：无颗粒、无网点、无纸纹、无渐变。

## 09 运动语汇

| 项 | 值 |
|---|---|
| 时长 | 240 / 360 / 480ms |
| 曲线 | `cubic-bezier(.34, 1.32, .64, 1)` |
| 入场 | **由凹到凸**：从内影顶出为外影 |
| 退场 | 反向压回凹陷 |
| 位移 | ≤4px |
| 背景 | **静止** |

实现提示：两层伪元素分别承载内影与外影，用透明度交叉过渡，比直接动画 `box-shadow` 流畅。

## 10 组件映射

| 组件 | 在这套语言里 |
|---|---|
| 大数字 | 凹陷槽 + 槽内凸起的数字牌 |
| 数据卡 | 凸起面板，每个字段各占一个凹陷槽 |
| 引语 | 整块凹陷——像压进底面的印章 |
| 章节卡 | 凸起面板 + 左侧小凹陷槽放序号 |
| 对比 / 进度 | 凹陷轨道 + 凸起滑块 |

## 11 容错与边界

| 情况 | 处理 |
|---|---|
| 文字对比 | 正文 ≥ `#3D4A5C`；`#6B7A90` 最小 20px；`#97A3B5` 仅 ≥24px |
| 元素相邻 | 两个凸起间距 ≥24px |
| 一屏数量 | 凸起 ≤3、凹陷 ≤5 |
| 层次上限 | 最深到 L3。不做遮罩与模态 |
| 深色降级 | 画布 `#2A2F3A`，亮影降至 6%、暗影加深至 30%，只保留 L1 / L2 |
| 长文本 | 卡片内正文 ≤3 行，超出拆成两张卡 |
| 超长数字 | 超过 6 位改用万 / 亿并留一位小数，字号降一档 |

## 12 画幅与载体

同一套语言三种载体，差别在「桌面由谁提供」。

| 载体 | 画布 | 本套取值 |
|---|---|---|
| 横版成片 | 1920×1080 | 板宽 62%，重心垂直 42% |
| 竖版成片 | 1080×1920 / 1080×1440 | 板宽 88%，组件换型 |
| 竖版透明素材 | 1080×1440 | **必须自带承载板** |

| 横竖重排 | 横版 | 竖版 |
|---|---|---|
| 对比卡 | `c-vs` 横排 A≠B | 换 `c-cmp` 上下两块 |
| 步骤 | `c-step` 等宽并列 | 换 `c-stack` 阶梯堆叠 |
| 数字字号 | 190px | 158px（3:4）/ 140px（9:16） |
| 侧列式骨架 | 左 38% + 右 62% | 改上下 42% / 58% |

模板给的 `max-width:76%` 是安全上限，本套**永不触碰**——76% 的卡片横跨大半个屏，凸起的物件感会退化成「一块板」。

### 12·A 透明载体的承载板

透明底没有桌面，柔影没有落点。**产物必须自己画一块承载板**，板以外保持全透明。

| 项 | 值 | 说明 |
|---|---|---|
| 板色 | `#E4E9F0` | 与元素填充色必须同值，否则凸起失效 |
| 不透明度 | 实心（首选）或 ≥0.96 | α=0.94 时画面细纹理已可见 |
| 边缘 | 实心板 + 40px 羽化 | 硬边读作「贴上去的卡片」，羽化读作软窗口 |
| 磨砂 | **不可用** | 透明模式下页面无画面可虚化，模板写死 `backdrop-filter:none` |
| 深色变体 | 板 `#2B3238`，亮影 `rgba(255,255,255,.07)`，暗影 `rgba(0,0,0,.55)` | 叠在亮实拍上对比更强，透明支线推荐方向 |

三条实测结论：① 板若用**纯白**，左上白影落在白底上直接消失，凸起退化成普通投影，且板上元素比板更暗→「同色」前提被破坏（凹陷反而幸存，它的亮影是内影、自带底色）。② **实心板 + 40px 羽化**内部零漏液，保住第 08 节的「零纹理」。③ 半透明漏进来的纹理，与模板那条「透明底没有『纸』，纹理必须全关，否则导出后变成浮动脏条纹」是同一件事。

板与板之间留 ≥1.5s 纯透明，同一时刻只有一块板。

## 13 幕与节奏

| 项 | 值 |
|---|---|
| 一屏几幕 | **1 幕**（组件块体积大，不做幕内叠加） |
| 每幕构件 | ≤3 个凸起 + ≤1 个凹陷槽 |
| 停留 | 单元素 ≥1.5s；关系型组件 3–5s |
| 幕内入场 | 元素逐个顶出，错开 120ms |
| 幕间过渡 | 上一幕压回凹陷 → 下一幕顶出 |
| 入场轮换 | 相邻幕至少换一种入场 |
| 背景 | **全片静止** |

幕间不加位移、擦出、模糊——都会打散「同一块表面」。静止是这套的定义，不是省事。

## 14 组件全映射

15 个组件都是**凸起与凹陷的组合**。

| 组件 | 在这套语言里 | 层次 |
|---|---|---|
| `c-data` | 凹陷槽 + 槽内凸起的数字牌 | L1 |
| `c-capsule` | 凹陷胶囊 | L0 |
| `c-kw` | 无容器，只靠字号与留白 | L1（极弱） |
| `c-vs` | 左右两块凸起 + 中缝 6px 凹陷缝 | L1 |
| `c-quote` | 整块凹陷 | L0 |
| `c-rule` | **凹陷细槽**（唯一分隔手法） | L0 |
| `c-list` | 每行一个凹陷槽，不加分隔线 | L0 |
| `c-bar` | **凹陷轨道 + 凸起填充条**（招牌） | L0+L1 |
| `c-ring` | 凹陷环槽 + 末端凸起端帽 | L0 |
| `c-line` | **不参与凸凹**，只靠明度与粗细 | — |
| `c-step` | 凸起面板 + 左侧凹陷序号槽 | L1 |
| `c-note` | 凸起小面板，不歪斜不折角 | L1 |
| `c-flow` | 两块凸起 + 凹槽里的箭头 | L1 |
| `c-stack` | 每级一个凸起块，宽度递减 | L1 |
| `c-cmp` | 上下两块凸起 + 中缝凹陷槽 | L1 |

**分隔件裁决**：别家用 `border-top` / 发丝线；本套用**凹陷横槽**（高 6px、inset 双影），清单、表格、引语、坐标轴全用它。禁止任何 `border` / `1px solid` / 虚线。

两个硬骨头：① `c-line` 折线没有体积，凸凹语汇用不上——线只靠 `--ink`（2.5px 粗）与数据点（8px 凹陷小孔）区分。② `c-ring` 的弧做不出厚度——改「凹陷环槽 + 末端凸起端帽」，弧只画槽。

### 15·A 专属动效

既有 13 种入场**没有一种适合本套**——全是位移、擦出、缩放、模糊，没有一种「从表面顶出来」。keyframes 直接作用在 `.comp` 上（这套把 `.comp` 本身当作板），不用给每个组件各写一套。

```css
@keyframes embossin{                    /* 由凹到凸 */
  0%  {opacity:0; transform:scale(.965);
       box-shadow:inset -4px -4px 9px rgba(255,255,255,.92),
                  inset  4px  4px 10px rgba(163,177,198,.50);}
  38% {opacity:1;}
  100%{opacity:1; transform:scale(1);
       box-shadow:-6px -6px 12px rgba(255,255,255,.92),
                   6px  6px 14px rgba(163,177,198,.55);}
}
@keyframes sinkout{                     /* 压回凹陷 */
  0%  {opacity:1; transform:scale(1);
       box-shadow:-6px -6px 12px rgba(255,255,255,.92),
                   6px  6px 14px rgba(163,177,198,.55);}
  100%{opacity:0; transform:scale(.972);
       box-shadow:inset -4px -4px 9px rgba(255,255,255,.92),
                  inset  4px  4px 10px rgba(163,177,198,.50);}
}
```

注册（**必须先注册再用**，入场映射逐字匹配，名字不认识时不报错——那块板只是不动）：

```css
body.animate .comp.in[data-anim="EMBOSS-IN"]{animation:embossin .36s cubic-bezier(.34,1.32,.64,1) both}
body.animate .comp.out[data-out-anim="SINK-OUT"]{animation:sinkout .24s ease-in both}
```

**语言边界（动效）**：只用 `EMBOSS-IN`（凸起件）/ `SCALE-POP`（数字件，模板已有）/ `FADE-IN`（凹陷件，模板已有）三种。只注册 `EMBOSS-IN` 就够，另两种模板里已有，刚好凑满 ≥3 种入场的硬线。

## 16 在场演化

前十五节管的是「板长什么样、怎么出现」。只做到这一步，一块板停 5 秒有 4 秒是死帧——**信息本身还没动**。数字该从 0 涨上来、条该从槽里挤出来、大和小该被演成一次对比。

**一条硬事实**：模板自带的 `.num` 计数器在这条流水线里是废的。它走 `requestAnimationFrame`，而渲染器每取一帧都调 `IVH.seekAt()`，里面那句 `freezeCounters()` 把数字**直接写成终值**——成片里从第一帧到最后一帧都是终值。**所以任何会变的数字都必须做成 CSS 动画。**

### 16·A 数字跳涨

```css
@property --nv  {syntax:"<integer>"; initial-value:0; inherits:false}
@property --nto {syntax:"<integer>"; initial-value:0; inherits:false}

@keyframes numcount{ from{--nv:0} to{--nv:var(--nto)} }

.num-up{
  counter-reset:nv var(--nv);
  animation:numcount 1.05s cubic-bezier(.22,.9,.28,1) both;
  animation-delay:.34s;                  /* 等板先顶出来，再开始跳 */
}
.num-up::after{content:counter(nv)}      /* 元素内留空，文本全由 counter 出 */
.num-up[data-tick]{animation-timing-function:steps(12,end)}   /* 逐格跳的手感 */
```

用法：`<span class="num-up" style="--nto:78"></span>`

四个坑：

- 元素内**不能放文本**——`::after` 会把 counter 追加在原文之后，写「78」会渲染成「780」
- **只能整数**——`counter()` 不接受小数，要小数就拆成整数位与小数位两段分开跳
- `animation-delay` 必须写在 `animation` **简写之后**，否则被重置为 0
- 数字牌要**跟着跳一下**（`numkick`：每跳一拍把柔影从「凸」顶到「更凸」）——用影的深浅表现重量，不用位移

### 16·B 柱条生长

模板给 `.c-bar .fill` 挂的是 `grow`（`scaleY` 纵向生长）。对一条 18px 高的填充条来说，纵向生长看着只是「变粗」，跟长度无关。本套要横向挤出，且过程中柔影由内凹翻成外凸——所以它不是「变长」，是**从凹陷里被顶出来的实体**。

```css
@keyframes bargrow{
  0%  {width:0%; opacity:0;
       box-shadow:inset -3px -3px 6px rgba(255,255,255,.90),
                  inset  3px  3px 7px rgba(163,177,198,.50);}
  14% {opacity:1;}
  56% {box-shadow:inset -1px -1px 3px rgba(255,255,255,.90),
                  inset  1px  1px 3px rgba(163,177,198,.45);}
  100%{width:var(--w); opacity:1;
       box-shadow:-3px -3px 7px rgba(255,255,255,.95),
                   3px  3px 8px rgba(163,177,198,.60);}
}
```

- 宽度走 `--w`（`<div class="fill" style="--w:78%">`），**不读内联 `width`**——关键帧的终值要能引用元素自己的值
- 行间错开 0.16s；**数字晚于条 0.5s**——条先挤出、数字随后到，眼睛才有落点

### 16·C 大小对比

「比较」不是把两个数并排放好，而是让它们**演一次音量差**：起手时大的还是凹的、小的还是凸的，收尾时各自归位。中间那一拍反转，才叫对比。

```css
@keyframes bigup{                        /* 大的：从沉的顶上来 */
  0%  {transform:scale(.84); box-shadow:var(--n-in-sm)}
  62% {transform:scale(1.045)}
  100%{transform:scale(1);   box-shadow:var(--n-out)}
}
@keyframes smalldown{                    /* 小的：从凸的沉下去 */
  0%  {transform:scale(1.20); box-shadow:var(--n-out)}
  100%{transform:scale(.90);  box-shadow:var(--n-in-sm)}
}
```

两者 delay 差 0.16s：小的先沉、大的后顶。组件用 `c-cmp`，但要覆写掉它的 `border` 与 `text-decoration:line-through`——两者都违反本套（§03 零形变、§04 禁描边线）；中缝的 `.vs` 直接不显示，分隔交给间距。

### 16·D 循环与边界

另外两个配套动作（写法和上面同构）：

```css
@keyframes pressin{                     /* 清单行：从更深地压进底面回到正常凹陷 */
  0%  {opacity:0; transform:translateY(-7px);
       box-shadow:inset -7px -7px 14px rgba(255,255,255,.95),
                  inset  7px  7px 15px rgba(163,177,198,.62);}
  100%{opacity:1; transform:none; box-shadow:var(--n-in-sm);}
}
@keyframes breathe{                     /* 柔影呼吸：0%/100% 必须等于该元素的基础态 */
  0%,100%{box-shadow:var(--n-in)}
  50%    {box-shadow:inset -6px -6px 13px rgba(255,255,255,.94),
                     inset  6px  6px 15px rgba(163,177,198,.58);}
}
```

| 动作 | 用在哪 | 什么时候别用 |
|---|---|---|
| NUM-UP 数字跳涨 | 单个指标当论点，停留 ≥2s | 一屏三个以上数字同时跳（互相打架）；数字本身不是论点时 |
| BAR-GROW 柱条生长 | 占比、构成、同一口径的几条对比 | 数值差小于 5%——长度差看不出来，改用数字跳涨 |
| SCALE-CMP 大小对比 | 两件事的音量差 | 三件以上（对比退化成排队）；两块尺寸本来就相等时 |
| PRESS-IN 行压入 | 清单、步骤、逐条给 | 行数超过 5 行——最后一行要等到 0.7s 之后 |
| BREATHE 柔影呼吸 | 全片只给一个元素，表示「它活着」 | 板上出现第二个；幅度超过 25%（会变成发光） |

**本套的额外约束**：

- **不用位移表达弹性**——本套的「动」由影的深浅与形状的进出承担。位移只保留 7px 这一个量级（行压入），再多就变成别的风格了
- **数字牌必须跟着跳**——只有数字变、牌不动会像贴纸。每跳一拍把柔影从「凸」顶到「更凸」，用影的深浅表现重量
- **呼吸全片只留一处**——板上出现第二个不同步的呼吸，会读成「界面坏了」。这也是本套唯一的循环动效
- **动作数 < 幕数**——一屏里同时演出的动作不超过两个，三个以上会互相抢注意力

公共层那三条硬规定（一个元素只挂一个动画 / 循环动效首尾帧等于基础态 / 新动画名逐字注册）本套同样适用，写法与实测见 `design-specs/motion-spec.md` §1.3 与 §2④，此处不重复。
