# 柔面凸凹 · Soft Relief — 透明素材

> 整个画面只有一个颜色。所有东西靠同一道光源的两侧柔影，从底色上被"托起来"或"压下去"。
>
> soft / tactile / quiet · 画面本身就是一件物件。

**谁读这份：**

- **写脚本的人** —— 只读第五节的表（白话名 → 画成什么、容量）和第六节的硬约束。**永远不要写类名。**
- **生成 HTML 的人** —— 读第三、五、八节，然后去 `template.html` 的样板间照抄。

> **`components.html` 是这套风格的零件库**（10 个场景模板 / 12 个内容组件 / 7 个小元素 /
> 5 个数据可视化 / 5 种专属动效 / 3 种版式骨架 / 深色降级）。**画法不够用时去那儿找形态。**
> 但它**不是契约** —— 产物只认本文件的第五、六、八节，两边不一致时以本文件为准。

## 一、画幅与承载板

```
1080 × 1440（3:4）        板外全透明
┌──────────────────────┐
│                      │
│   ╭──────────────╮   │  ← 承载板：不透明 #E4E9F0
│   │              │   │     宽 ≈72%，圆角 40，垂直居中
│   │   凸凹组件   │   │
│   │              │   │
│   ╰──────────────╯   │
│                      │
└──────────────────────┘
```

**板跟着点走。** 板不是一张常驻画布 —— 它是**每个点自己的**：点进板进，点走板走。
两点之间必须一个像素都不留，实拍才露得出来。**一个点 = 一块板。**

**为什么必须有承载板**：这套语言靠"底色 + 两侧柔影"制造凸凹。底一旦透明，柔影没有依托，凸凹就散了——凸起的东西会看起来像悬浮的污渍。

**承载板只加单侧暗投影。**

```css
/* 对：一侧暗影，读作"板落在实拍上" */
box-shadow: 10px 14px 30px rgba(20,28,40,.22);

/* 错：两侧柔影，亮影在透明底上会变成白色光晕 */
box-shadow: -10px -10px 24px #fff, 10px 10px 30px rgba(163,177,198,.5);
```

**可读性**：本风格**靠承载板**保证——文字永远压在 #E4E9F0 上，不需要描边，不需要柔影。

> 用户在剪辑时另加的半透明黑 / 白底，是为了让这块板从原片里"跳出来"，与本产物无关，spec 不管。

**不需要深色降级。** 产物自带不透明承载板，不随宿主画面变明暗。

## 二、材质与层次

**光源恒定左上 315°，永不改变。** 凸起用外影，凹陷用内影。

```css
--lit: #FFFFFF;   /* 亮影白 · 材质，光源侧 */
--dim: #A3B1C6;   /* 暗影灰 · 材质，背光侧 */

/* 凸起（外影） */
box-shadow: -6px -6px 12px rgba(255,255,255,.92),
             6px  6px 14px rgba(163,177,198,.55);

/* 凹陷（内影） */
box-shadow: inset -5px -5px 10px rgba(255,255,255,.92),
            inset  5px  5px 12px rgba(163,177,198,.50);
```

亮影白与暗影灰是**材质**，不是颜色，不参与配色计算。

| 级 | 形态 | 用于 |
|---|---|---|
| L0 | 无影 | 承载板本身 |
| L1 微凸 | 外影 6 / 6 | 元素默认态 |
| L2 抬起 | 外影 10 / 10 + 上移 2px | 当前项（本产物很少用） |
| L3 凹陷 | 内影 5 / 5 | 轨道、凹槽、选中的一层 |

**最深到 L3。** 不做遮罩、不做模态——这是 3:4 的一块板，套不进弹窗。

**禁止 `border` / `1px solid` / 虚线。** 分隔一律用**凹陷横槽**（高 6px，inset 双影）。这是本套唯一的划分手法。

## 五、白话名 → 画成什么（核心表）

`kind` 从 `../extract.md` 第四节来。**写脚本只用第一列和最后一列。**

| `kind` | 画成什么 | 类名 | `blocks` 形状 | 容量 |
|---|---|---|---|---|
| `大数字` | 凸起面板；数字直接放板上，下面一条凹陷归因槽 | `c-data` | `[{ value, caption }]` | 归因 ≤10 字 |
| `占比` | 凹陷环槽 + 末端凸起端帽 | `v-ring` | `[{ pct, caption }]` | 说明 ≤6 字 |
| `数值比大小` | 每行一条凹陷轨道 + 凸起填充条 | `v-bar` | `[{ t, v }] × 2~4` | 标签 ≤6 字 |
| `趋势` | **不参与凸凹**（线没有体积），只靠明度与粗细 | `v-line` | `[{ caption }]` | 说明 ≤10 字 |
| `进度` | 凹陷轨道 + 凸起滑块 | `v-progress` | `[{ pct, caption }]` | 说明 ≤6 字 |
| `数字对比` | 两块凸起，起始等大，随后一大一小 | `v-compare` | `[{ t, v }, { t, v }]` | 每侧 ≤6 字 |
| `转化` | 上块凸起 → 凹陷箭头槽 → 下块凸起 | `c-flow` | `[{ t, v }, { arrow }, { t, v }]` | 关系标签 ≤6 字 |
| `对照` | 上下两块凸起 + 中缝凹陷槽 | `c-cmp` | `[{ label, text }, { label, text }]` | label ≤4 字，text ≤6 字 |
| `三步递进` | 每级一个凸起块，宽度递减 | `c-stack` | `[{ t, v }] × 2~3` | 每级 ≤6 字 |
| `关键词 + 释义` | 无容器的关键词 + 凹陷槽里的释义 | `c-kw` + `c-note` | `[{ term, def }]` | 词 ≤6 字，释义 ≤16 字 |
| `章节标记` | 凸起面板 + 左侧凹陷序号槽 | `c-step` | `[{ idx, title }]` | 标题 ≤8 字 |
| `引语` | 整块凹陷，文字直接放槽里 | `c-quote` | `[{ text, by? }]` | text ≤24 字，by ≤14 字 |
| `清单` | 每行一个凹陷槽，不用分隔线 | `c-list` | `[{ item }] × 2~4` | 每行 ≤10 字 |

### 三档形态（脚本只给白话名，类名在这一步才换算）

形态写在 `.comp` 上 —— 和霓虹那套（壳写在 `.pnl` 上）不一样，因为这套是"板"的语言。

| 白话名 | 类名 | 长什么样 | 谁用 |
|---|---|---|---|
| `凸起` | `raise` | 从底板上凸出来一块 | 结论、当前项 —— **一块板最多一个** |
| `凹陷` | `sunk` | 往底板里陷进去一块 | 旧的、被否掉的、背景信息 |
| `无板` | `bare` | 不占板，字直接落在承载板上 | 绝大多数：数字、清单、词条、引语 |

**规则：** 脚本的每个点写一个白话名（`points[n].form`），生成 HTML 时才换算成类名。
`凸起` 和 `凹陷` 都很少用 —— 这套的默认答案是 `无板`，只有真的要"一个东西压在另一个上面"时才动它。

### 表里写死的判别规则

**别让生成 HTML 的那一环临场发挥**——同一份脚本跑两次必须长得一样。

| 情况 | 用哪个 |
|---|---|
| `对照` | 一律 `c-cmp`（上下两块）—— 竖版天生竖排，而且 `label` 有位置放 |
| `数值比大小`，2~4 行 | `v-bar` |
| `数值比大小`，5 行以上 | 拆成两个点，或改 `c-list` |
| `趋势`，只要一条线 | `v-line`（折线**形状固定**用样板间那条 —— 脚本不给数据点，不许自己编点） |
| 数字要配一段解释 | `c-data`（归因槽） |
| 数字要和另一个数字比 | `数字对比` |

**全部走竖排**（`c-cmp` / `c-stack` / `c-flow`）。1080 宽的板里，横排的两块会被挤成窄条，而且没有位置放 `label`。

## 八、动效

**本套的"动"由影的深浅与形状的进出承担。**

```css
@keyframes sr-emboss{   /* 由凹到凸：内影顶出为外影 */
  0%  {opacity:0; transform:scale(.965);
       box-shadow: inset -5px -5px 10px rgba(255,255,255,.92),
                   inset  5px  5px 12px rgba(163,177,198,.50);}
  100%{opacity:1; transform:scale(1);
       box-shadow: -6px -6px 12px rgba(255,255,255,.92),
                    6px  6px 14px rgba(163,177,198,.55);}
}
@keyframes sr-sink{     /* 压回凹陷 */
  0%  {opacity:1; transform:scale(1);}
  100%{opacity:0; transform:scale(.975);}
}
@keyframes sr-press{    /* 行压入：位移 7px */
  0%  {opacity:0; transform:translateY(-7px);}
  100%{opacity:1; transform:translateY(0);}
}
```

| 名 | 时长 | 手感 |
|---|---|---|
| `EMBOSS-IN` | 360ms | 由凹到凸，内影顶出为外影。**默认入场** |
| `PRESS-IN` | 300ms | 从更深地压进底面，位移 7px。逐行、逐级用 |
| `SINK-OUT` | 240ms | 压回凹陷。**默认退场** |
| 数字跳涨 | 1050ms | 数值从 0 滚到目标，由渲染器按时刻算出 |

**退场统一 `SINK-OUT` 240ms。** 在这套语言里，"消失"就是压回底面，不需要花样。

### 默认配方（按 `kind` 给，生成 HTML 时不临场发挥）

| `kind` | 入场 |
|---|---|
| `大数字` | `EMBOSS-IN` + 数字跳涨 |
| `占比` | `EMBOSS-IN` + 环槽从 12 点顺时针生长 |
| `数值比大小` | `EMBOSS-IN` + 填充条从左生长，错峰 140ms |
| `趋势` | `EMBOSS-IN` + 线段与点一起揭开（`clip-path` 从左到右） |
| `进度` | `EMBOSS-IN` + 滑块从左往右 |
| `数字对比` | `EMBOSS-IN` + 等大 → 一大一小 |
| `转化` | `EMBOSS-IN` + 箭头自上往下走 |
| `对照` | `EMBOSS-IN` + 上块下拉、下块上推 |
| `三步递进` | `PRESS-IN` 逐级，错峰 120ms |
| `清单` | `PRESS-IN` 逐行，错峰 100ms |
| `关键词 + 释义` | `EMBOSS-IN` |
| `章节标记` | `PRESS-IN` |
| `引语` | `EMBOSS-IN`，慢一档（440ms） |

### 持续态

**亮着的时候也在动：板在呼吸。** 相位由引擎写的 `--hold`（距入场多少秒）决定，同一个 `t` 永远渲染出同一帧。

```css
@keyframes sr-platebreathe{
  0%,100%{box-shadow:10px 14px 30px rgba(20,28,40,.22)}
  50%    {box-shadow:6px  9px 22px rgba(20,28,40,.14)}
}
.comp.in::before{
  animation:sr-platebreathe 3.2s ease-in-out infinite;
  animation-play-state:paused;
  animation-delay:calc(var(--hold,0s) * -1);
}
```

**幅度只有 6px，每个点都在呼吸。** 这套语言里"一直在动"不能被看见，只能被感觉到——整块板在实拍上极缓慢地起落。
反过来，**产物里不许出现完全静止的画面**：板一旦停住，这一块就从实拍上"掉"下来了。

**一条产物内至少出现 3 种不同的入场手感。** 全片一个手感等于没设计。
