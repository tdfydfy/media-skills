# ivh-next · 口播视频的透明叠加素材

给定**别人的口播视频 + 字幕**，产出**几块 1080×1440 的透明素材**，回头叠到原片上，把口播里"看不见的结构"（对比、流向、占比、递进）摆出来。

素材自带不透明承载板，所以**在任何画面上都能读**；用户在剪辑时另加的半透明黑 / 白底是为了让这块板从原片里跳出来，与本仓库无关。

---

## 三步，两道闸门

```
 原片 + SRT
     │
     ▼
 ①  提取       读 extract.md            →  脚本.json（分章 + 内容 + kind + 时间码）
     │
     ├──── 闸门 1 · 文本确认 ────────────────────────┐
     │      只读 JSON / MD，不看画面。              │
     │      改的是：全片分几章、挑哪句、压成什么字、 │
     │      关系对不对、落在第几秒。改到满意再过。   │
     ▼                                              │
 ②  生成 HTML  读 build.md + 该风格 spec.md          │
     │          抄 template.html 的样板间            │
     │           →  脚本.html                      │
     ├──── 闸门 2 · 效果确认 ────────────────────────┘
     │      浏览器里看动的样子（?kit=1 对比样板间、
     │      ?t=秒 定格某帧）。改的是抄哪块、删哪行。
     ▼
 ③  渲染       走 ivh-render（已可用，本目录不管）
                →  透明 WebM / PNG 序列
```

**两道闸门分开放**是故意的：闸门 1 改文字，闸门 2 改画面。混在一起就会出现"因为一个字不好看，把整个关系改了"。

## 先分章，再挑句

一条片子里的内容分两层。**顺序不能反**——先挑句子，挑出来的东西每句都对、合起来散架。

| 层 | 是什么 | 落成什么 `kind` |
|---|---|---|
| **骨架层** | 全片分 3~6 章（写进 `meta.outline`）；**片头必给一次全片目录**；口播里有"我讲三个方面"式概括句的地方给一次**局部提纲**；再有就是一句话报位置 | `目录` / `章节标记` |
| **内容层** | 每个意群一条素材点：对比、流向、占比、递进 | 其余 13 个 |
| **提醒层** | 那一节的核心词，单独拎出来亮一次 | `关键词` |

- **`目录` 一律逐条点亮，不许整块端上来。** 观众要能在你报第 4 章的时候还回想起第 1 章——
  一条一条亮起来才是一份**行程**，一整块出来只是一张图
- **片头那次是硬要求**，不是可选。全片第一个点就是它
- 同一个 `目录` 组件既报全片、也报局部提纲；区别只是后者多给一个 `cur`（当前讲到第几条），
  靠它把"已讲 / 当前 / 未讲"三态分开
- **局部提纲只在有概括句时做。** 口播说了"主要看三个方面"、而那三条散在后面一大段，才摆这一下；
  自然语言讲了几个点、没有那句概括，**就不做**——替观众总结是加戏（判据见 `extract.md` 第二节）
- **`关键词` 一条片子最多 3 个**，判据是"全片出现 ≥3 次"，不是"你觉得重要"（`extract.md` 第五节）
- **`目录` 不计入密度。** 它是同一张地图可能复现的东西，不是一句口播的内容；`章节标记` 照常算

## 文件地图

| 文件 | 谁读 | 讲什么 |
|---|---|---|
| `extract.md` | ① | **一份共用，不含视觉决定。** 全片分几章（`meta.outline`）、挑哪句、压成什么字、认哪种关系（15 个 `kind` 白话名）、落在第几秒 |
| `styles/<风格>/spec.md` | ①（只看第五、六节）<br>②（看第三、五、六、八节） | 这一风格把这些 `kind` **画成什么**、容量、硬约束、动效配方 |
| `styles/<风格>/template.html` | ② | 引擎 + 样板间 + 产物区。**② 只抄样板间** |
| `styles/<风格>/components.html` | ②（可选） | 该风格的**零件库** —— 场景模板、内容组件、小元素、数据可视化、版式骨架。形态不够用时翻它。**不是契约，冲突以 `spec.md` 为准**（目前只有 `soft-relief` 有） |
| `build.md` | ② | 从 `脚本.json` 到 `脚本.html` 的机械动作，含逐 `kind` 的填法表 |
| `check.mjs` | 人 | 机器能判的都在这儿判 |
| `example/` | 人 | 一份走完全程的样例：`script.md`（给人读）+ `script.json`（①的产物）→ `script.html`（②的产物） |

**这两份文档（`extract.md` / `build.md`）就是提示词。** 别另外维护一份"提示词"——提示词和规范分开写，两边必然会漂。

> ① 的唯一对接点是 `kind` 白话名；② 的唯一对接点是样板间里的 `<!-- kind: xxx -->` 锚点。
> 两条都是 grep 级的，`check.mjs` 双向核对。

## 怎么跑

```bash
# 闸门 1 之后（① 交脚本）—— 只查脚本
node ivh-next/check.mjs 脚本.json

# 闸门 2 之后（② 交产物）—— 多一节，逐点核对产物
node ivh-next/check.mjs 脚本.json 产物.html
```

浏览器打开 `script.html`：

| 加什么 | 看到 |
|---|---|
| 什么都不加 | **出片状态**：不铺底、不缩放、没有 HUD —— 渲染器就是这么打开它的 |
| `?view=1` | 深底预览，自动缩放，播一遍（给人看） |
| `?view=1&t=22.5` | 深底 + 定格在 22.5s |
| `?kit=1` | 样板间全部演示一遍（自带深底预览），拿来对比产物抄得对不对 |
| `?t=22.5` | 定格在 22.5s 这一帧，透明、无控件，**同一秒永远同一帧** |

## 加一个新风格要做什么

本目录**只放三个风格，彼此从设计语言到形状完全无关**，不考虑继承、复用、族。

新增一个风格，就加两样东西：

```
styles/<风格>/spec.md          从零写：画幅、材质、色彩、字体、白话名→画成什么、硬约束、动效
styles/<风格>/template.html    从零写：引擎可以照抄，视觉段和样板间必须重写
```

然后 `node check.mjs` 会自动核对两条对齐：

1. `extract.md` 第五节的 15 个 `kind` ↔ `spec.md` 第五节的 `kind` 列 —— **本风格不支持的要么补上，要么在 spec 里写清"降级成 X"**
2. `spec.md` 的每个 `kind` ↔ `template.html` 样板间里的 `<!-- kind: xxx -->` —— **双向，多一个少一个都算错**

新风格不必支持全部 13 个。**对不上的地方要写出来**，不要让写脚本的人自己猜。

## 跨风格的硬契约

每个风格都必须回答这两条，缺一条产物就是"PPT 一样的东西"：

1. **亮着的时候也在动。** 引擎把 `--hold`（距入场多少秒）写在 `.comp` 上；子元素的持续态用
   `animation-delay: calc(var(--hold,0s) * -1)` + `animation-play-state: paused` 自己算相位。
   相位由 `t` 唯一决定，所以同一个 `t` 永远渲染出同一帧——**持续态必须是可定格的**，否则渲染器拍不准。
2. **每个点里至少一处持续态。** 全片不许出现完全静止的画面。

> 入场（`.comp.in[data-anim]` 与 `.comp.in .stg`）只管"怎么出现"，持续态管"出现之后"。
> 两者不能挂在同一个元素上——同一个 `animation` 会互相覆盖。
