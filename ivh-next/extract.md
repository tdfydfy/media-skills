# 提取指引

**这份是共用的，不含任何视觉决定。** 它只回答四件事：挑哪句、压成什么字、这是哪种关系、落在第几秒。

"挑出来之后画成什么"在各自风格的 `spec.md` 里。两份文件唯一的对接点是第四节那批 **`kind` 白话名**。

读者：写脚本的那一步（产出 `脚本.json` 的人）。

---

## 一、你在做什么

一段别人的口播（SRT / 逐字稿）+ 一条别人的片子。你产出**一串素材点**：

```
口播时间轴 ─────────●─────────●───────●──────────→
                  素材点      素材点   素材点
                  （3~5s）    （3~5s）  （3~5s）
                     ← 大段全透明 →
```

每个点 = 一个时间区间 + 一个**关系** + 它的元素。

**口播负责"因为…所以…"，画面负责把这个关系摆出来。**

一块板上只有一个孤立的数字，那是**字幕卡**——口播已经说了，屏幕上再来一遍就是纯重复。放上「A → B」，它才承担了口播里"因为…所以…"那一层。

## 二、圈抓手：哪些句子值得停一眼

| 抓手 | 长什么样 | 例 |
|---|---|---|
| 数字 | 有刻度、有对比对象 | "转化率比一线高 1.8 倍" |
| 转折 | 否定 + 肯定 | "不是付费能力不行，是一直没去试" |
| 结构 | 带序数或分类 | "分三块来看"、"第一…第二…" |
| 定义 | "所谓 X 就是 Y" | "所谓渠道下沉，就是往低线城市走" |
| 代价 / 结果 | 因果的落点 | "结果获客成本只有一半" |
| 章节切换 | 明说换话题 | "接下来看第二个问题" |

**再宽一点的五种，也别放过：**

| 抓手 | 长什么样 | 例 |
|---|---|---|
| 关键动作 | 有人做了一件事 | "后台同步跟进多个客户" |
| 关键判断 | 说话人下了个结论 | "这单就很危险" |
| 风险信号 | 客户嘴里漏出来的细节 | "首付只有 10 万"、"明年 8 月结婚" |
| 反问 | 自己提出问题 | "以前的业务管理为什么这么难呢" |
| 痛点罗列 | 一串并列的坏情况 | "过程看不见、机会抓不住" |

**一个抓手都没有才跳过。** 三句里挑得出一句，就做。

**别怕密。** 上一版最大的毛病不是密，是**稀**——观众看着看着会以为这条片子没做。
一条 137s 的口播，出 20~30 个点是正常的，不是"太满"。
真正会变"第二块屏"的是**每张卡都很满**，不是卡多。**每张卡留白，卡与卡之间留空档。**

## 三、压：把一句话压成屏幕字

四步，一步不过就退回上一步。

| 步 | 动作 | 过关判据 |
|---|---|---|
| ① 抓 | 这句里**可量化**的东西是什么（数字 / 时间 / 对比 / 代价） | 一个都没有 → 回原文找数字，或跳过这句 |
| ② 论点 | 这些抓手合起来说明什么？写成一句**带因果**的话 | 别人听完不能接"所以呢" |
| ③ 主张 | **这句话的反面成立吗？** | 没人反对 = 共识 = 废话，退回 ① |
| ④ 屏幕字 | 压到该块的容量内：**一行小标题 + 2~4 个信息块**。不写主语、不写连接词，但**该有的信息一个不许砍** | 念出来和口播不一样，且**关上声音也看得懂** |

**第 ④ 步的常见错误是把"压"做成了"砍"。** 压是去掉主语、连接词、语气词；砍是把信息删掉。
「客户明年 8 月结婚，没有替代方案」压成「有风险」就叫砍——**观众要的是细节，不是形容词。**

一块板的信息量按这个估：**1 行小标题 + 2~4 个块**。只有一个块的板，先问自己是不是砍多了。

**第 ③ 步是分水岭。**「渠道下沉很重要」没人反对（共识）；「一线见顶，增量全在三四线」才有人反对——那才是主张。

**主张是要付代价的判断，没有代价的判断只是描述。**

### 一个真实的反差

原文：

> 只靠一线城市，到明年大概只能覆盖四成用户；把渠道下沉到三四线，会翻到七成以上。

| | 屏幕字 | 读起来 |
|---|---|---|
| 目录型 | 渠道策略 / 市场分析 / 结论 | 一份目录 |
| 提炼后 | 一线 40% → 三四线 70%+ | 一句话 |

两版信息量相同，区别只在**有没有压**。目录型对每句话都成立，所以对观众什么也没说。

## 四、认关系：这句话是哪种结构

**你在这里认出来的词，就是写进脚本的 `kind`。** 它是本文件和风格 `spec.md` 之间唯一的对接点。

| 口播在说什么 | `kind` | 画面要承担 |
|---|---|---|
| "从 A 变成 B" | `转化` | 方向 |
| "不是 A，是 B" | `对照` | 对立 |
| "第一…第二…第三" | `三步递进` | 顺序 |
| "涨了 37%" | `大数字` | 单一数值 + 归因 |
| "其中三线占一半" | `占比` | 部分与整体 |
| "从 2023 到 2026 一路走高" | `趋势` | 变化 |
| "A 比 B 高" | `数值比大小` | 量差 |
| "所谓 X 就是 Y" | `关键词 + 释义` | 定义 |
| "接下来讲第二点" | `章节标记` | 位置 |
| "已完成六成" | `进度` | 完成度 |
| 金句、结论 | `引语` | 分量 |
| "三个原因：…" | `清单` | 并列 |
| "A 组和 B 组差多少" | `数字对比` | 落差 |

**怎么选：**

- 口播里有方向（"变成"、"导致"、"下沉到"）→ `转化`
- 两块对等、没有方向 → `对照`
- 有先后顺序 → `三步递进`
- 只有一个数字，没有对照对象 → 先确认它有没有"跟谁比"；没有就退回第二节，这句可能不该做点

**选错不会报错，只会让画面说错话。** 关系和句子，只能有一个承担——如果口播已经说了"不是 A，是 B"，画面再摆一遍文字对比就是重复；画面该承担的是**对立**这个形状。

## 五、定时间：落在第几秒

| 类型 | 入点 |
|---|---|
| 具体数值（`大数字` / `占比` / `数值比大小` / `进度`） | 那句数字**说完之后 +0.3s** |
| 结构与关系（`转化` / `对照` / `清单` / `三步递进` / `章节标记`） | 它要讲的那句话**开始时** |
| 概念 / 名词（`关键词 + 释义`） | 与口播**同步**（首次出现的新名词） |
| 金句（`引语`） | 金句的**后半句**落下时（前半句是铺垫，卡在后半句整句才读得全） |

**分界线是"会不会剧透具体数值"。**

- **数值必须后置**：观众还没听到 10 万，屏幕上先冒出"10 万"，这一下就废了
- **结构必须前置**：转化、对照、清单是在给这段话搭架子，架子要在话**开始**的时候就在。
  等到说完才出，画面永远慢半拍——观众听到的是"首付只有 10 万"，看到的是另一件事，
  对不上就是这么来的

一句话：**先给架子，后给数字。**

- 停留 **3~5s**：素材自己撑住，不跟着句子结束。**多行的点按行算**，
  每行差不多 1.5~2s（四行清单 ≈ 7s 是正常的，不是拖）
- 相邻点之间留 **≥1.5s 纯透明空档**：让实拍主体露出来。**空档超过 8s 就说明漏了点** —— 观众会以为这条片子没做
- 点与点**不重叠**：一块板同一时刻只有一组元素
- **盖到片尾**：最后一个点的 `end` 距音轨结束不得超过 **6s**。末尾空一大截，等于没做完

**时间码永远来自音轨，不要估。** 拿不到 SRT 就先停下问用户要。

## 六、定密度：一条片子出几个点

| 体裁 | `contentType` | 原片长什么样 | 每 60s |
|---|---|---|---|
| 数字型 | `data` | 研报 / 口播 / 复盘 | 8~12 |
| 叙述型 | `narrative` | 故事 / 案例 / 科普 | 6~10 |
| 剧情型 | `drama` | 剧情 / 短剧 | 3~5 |
| 观点型 | `opinion` | 观点 / 评论 | 10~14 |

**往上沿走，别贴下沿。** 落在下沿的产物，观感就是"半天不出东西"——密度表的数字是**及格线到上限**，不是"够用就行"。

**超上限不是"内容多"，是叠加层变成了第二块屏。**

## 七、交付：脚本 JSON

```json
{
  "meta": {
    "style": "soft-relief",
    "title": "渠道下沉带来的结构性增长",
    "ratio": "3:4",
    "duration": 62.4,
    "contentType": "data"
  },
  "voiceover": [
    { "i": 1, "start": 0.0, "end": 3.8, "text": "我们先看一组反常的数据。" }
  ],
  "points": [
    {
      "i": 1,
      "kind": "转化",
      "form": "折叠",
      "kick": "对话到建议",
      "start": 12.6,
      "end": 16.8,
      "blocks": [
        { "t": "一线城市", "v": "40%" },
        { "arrow": "渠道下沉" },
        { "t": "三四线", "v": "70%+" }
      ]
    }
  ]
}
```

- `blocks` 是数组，长度和键由 `kind` 决定——**每个 `kind` 要什么，写在风格的 `spec.md` 里**
- `kick` 是这张卡的小标题（**每张卡都要有**，≤12 字）。它写"这卡在讲什么"，
  `blocks` 写"具体是什么"，**两个不许重复**（✓ kick「定义」+ term「业务闭环」）
- `kick` 不是给人念的，是给观众**扫**的。写成一句完整的话就是写错了
- `form` 是这个点想长什么样，用**白话名**写，**永远不许写类名**。
  **这个风格有哪几档、各自长什么样、什么时候用，写在该风格 `spec.md` 第五节的「形态 / 壳」表里**
  （`neon-terminal` 是 `带底` / `折叠` / `亮条` / `括标` / `无壳`；`soft-relief` 是 `凸起` / `凹陷` / `无板`）。
  还没定就用风格 `spec.md` 里第一档，别自己编一个名字
- `form` 只是"我打算用什么样的形式"这个标签；**具体换算成哪个类名、配哪个动效，是生成 HTML 那一步的事**
- **相邻两个点的 `form` 尽量不一样**。同一个 `kind` 连着出现，就靠换 `form` 拉开——
  21 个点全长一个样，观众第三眼就不看了
- `meta.style` 决定用哪份 `spec.md`；`meta.ratio` 恒为 `3:4`（透明素材的画幅）
- 再给一份同名 `.md`，给人看

## 八、自检

- [ ] 每个点都指得回一句口播，时间上贴着
- [ ] 每个点都**承担一个关系**（对照 / 流向 / 递进 / 占比）。只有一个孤零零的值，退回第三节重压；`引语` 和 `章节标记` 例外，它们本身就是一件事
- [ ] `kind` 是从第四节那张表里挑的
- [ ] `start` 落在句子结束后 +0.3s（数字型）
- [ ] 停留 ≥3s，相邻空档 ≥1.5s，点与点不重叠
- [ ] 密度落在 `contentType` 的档位内
- [ ] 时间码来自音轨，不是估的
