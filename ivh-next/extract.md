# 提取指引

**这份是共用的，不含任何视觉决定。** 它只回答五件事：全片分几章、挑哪句、压成什么字、这是哪种关系、落在第几秒。

"挑出来之后画成什么"在各自风格的 `spec.md` 里。两份文件唯一的对接点是第五节那批 **`kind` 白话名**。

读者：写脚本的那一步（产出 `脚本.json` 的人）。

---

## 一、你在做什么

一段别人的口播（SRT / 逐字稿）+ 一条别人的片子。你产出**一串素材点**：

```
口播时间轴 ─────────●─────────●───────●──────────→
                  素材点      素材点   素材点
                  （3~5s）    （3~5s）  （3~5s）
                     ← 大段全透明 →
```

每个点 = 一个时间区间 + 一个**关系** + 它的元素。

**口播负责"因为…所以…"，画面负责把这个关系摆出来。**

一块板上只有一个孤立的数字，那是**字幕卡**——口播已经说了，屏幕上再来一遍就是纯重复。放上「A → B」，它才承担了口播里"因为…所以…"那一层。

**先看全片，再看句子。** 顺序反了，你会挑出一堆每句都对、合起来散架的素材点——观众能看清每个细节，却拼不出这条片子的结构。所以第二节先干全局那件事。

---

## 二、先搭骨架：全片分几章

**在挑任何一句之前做这一步。** 通读全片，把它切成 **3~6 个章节**：每章是一个能独立说得清的**话题段落**，有开头、有落点。

写进 `meta.outline`：

```json
"outline": [
  { "idx": "01", "title": "渠道结构变化", "start": 12.0, "end": 48.5 },
  { "idx": "02", "title": "一线为什么见顶", "start": 48.5, "end": 96.0 },
  { "idx": "03", "title": "三四线怎么接", "start": 96.0, "end": 137.0 }
]
```

- `title` 写**话题**（「一线为什么见顶」），不写占位（「第一部分」「背景介绍」）
- ≤8 字。观众扫一眼就要知道这一段在讲什么
- 章节边界跟着**话题**走，不跟着句子走。一段话讲完了就切，别按时间均分
- 3~6 章。少于 3 章说明还没读出结构，多于 6 章说明你在切句子不是在切话题

**为什么要先做**：`目录` 要报的章节名、`章节标记` 要报的位置、`关键词` 要认的锚，全都从这张表来。先挑句子，这三样都只能临时编，编出来彼此对不上。

### 目录：片头必给一次，局部只在"有概括句"时给

`目录` 属于**跨句**那一类——它不来自任何一句口播，而来自**整条片子**或**一整个论点群**。
两种用法，同一个 `kind`：

**① 全片目录 —— 硬要求，每条片子片头必给一次。**

把 `meta.outline` 那张表整条报一遍。没有它，观众永远是听到一半才知道自己在哪儿。

**② 局部提纲 —— 口播给出"明确概括句"时才做。**

概括句 = 说话人**自己把下面几条数出来**的那一句：

| 口播 | 做不做 |
|---|---|
| "这个 XX，主要看三个方面，分别是…" | **做** |
| "三个核心逻辑" / "分两块讲" / "先讲三个问题" | **做** |
| "整个逻辑有四层" | **做** |
| "我举个例子，上个月有个客户…" | 不做——没数，是叙述 |
| 一口气讲了三件事，但**没有那句概括** | **不做**——替观众总结是加戏 |

**两个条件同时成立才做：**

1. **有明确概括句** —— 句子里有一个数量词（`三个` / `四个方面` / `两块` / `五步` / `几点`）
2. **那几条收得晚** —— 它们**不在这句话里列完**，而是散在后面几十秒里，讲到最后一条才收得回

**条件 2 是分水岭。**

- 「所以真正该做的是三件事：降成本、建层级、给锚点」——三条在**同一句**里就列完了 → 那是 `清单`
- 「三个核心逻辑」——三条分别在 1 分钟处、1 分 20 处、1 分 40 处 → 那是提纲

**为什么要卡概括句**：它是说话人递出来的钩子。他说了"接下来有三条"，观众此刻正竖着耳朵等第一、二、三条；
这时候把三条的名字摆出来是顺他的节奏。没有那句概括，观众不知道你在总结什么，一摆出来反而打断叙述。

**条目写什么**：那几条**自己的名字**，不是它们的解释。3~4 条最舒服，最多 6 条，字数与章节标题同一档（≤8 字）。

**和 `章节标记` 的分工**：提纲在概括句处**一次报全**（给 `cur` 标出讲到第几条）；
`章节标记` 是**逐条走到时各报一次位置**。两个不冲突，一起用最完整——先报地图，再一路标位置。

## 三、圈抓手：哪些句子值得停一眼

| 抓手 | 长什么样 | 例 |
|---|---|---|
| 数字 | 有刻度、有对比对象 | "转化率比一线高 1.8 倍" |
| 转折 | 否定 + 肯定 | "不是付费能力不行，是一直没去试" |
| 结构 | 带序数或分类 | "分三块来看"、"第一…第二…" |
| 定义 | "所谓 X 就是 Y" | "所谓渠道下沉，就是往低线城市走" |
| 代价 / 结果 | 因果的落点 | "结果获客成本只有一半" |
| 章节切换 | 明说换话题 | "接下来看第二个问题" |

**再宽一点的五种，也别放过：**

| 抓手 | 长什么样 | 例 |
|---|---|---|
| 关键动作 | 有人做了一件事 | "后台同步跟进多个客户" |
| 关键判断 | 说话人下了个结论 | "这单就很危险" |
| 风险信号 | 客户嘴里漏出来的细节 | "首付只有 10 万"、"明年 8 月结婚" |
| 反问 | 自己提出问题 | "以前的业务管理为什么这么难呢" |
| 痛点罗列 | 一串并列的坏情况 | "过程看不见、机会抓不住" |

**一个抓手都没有才跳过。** 三句里挑得出一句，就做。

**别怕密。** 上一版最大的毛病不是密，是**稀**——观众看着看着会以为这条片子没做。
一条 137s 的口播，出 20~30 个点是正常的，不是"太满"。
真正会变"第二块屏"的是**每张卡都很满**，不是卡多。**每张卡留白，卡与卡之间留空档。**

**反复出现的那个词要单独抓出来。** 说话人如果是靠一个词撑起整段的（黑话、造词、行业概念），
这个词会在几句里出现三次以上。**它值得单独成点** → `kind` 用 `关键词`（第六节有判据）。

## 四、压：把一句话压成屏幕字

四步，一步不过就退回上一步。

| 步 | 动作 | 过关判据 |
|---|---|---|
| ① 抓 | 这句里**可量化**的东西是什么（数字 / 时间 / 对比 / 代价） | 一个都没有 → 回原文找数字，或跳过这句 |
| ② 论点 | 这些抓手合起来说明什么？写成一句**带因果**的话 | 别人听完不能接"所以呢" |
| ③ 主张 | **这句话的反面成立吗？** | 没人反对 = 共识 = 废话，退回 ① |
| ④ 屏幕字 | 压到该块的容量内：**一行小标题 + 2~4 个信息块**。不写主语、不写连接词，但**该有的信息一个不许砍** | 念出来和口播不一样，且**关上声音也看得懂** |

**第 ④ 步的常见错误是把"压"做成了"砍"。** 压是去掉主语、连接词、语气词；砍是把信息删掉。
「客户明年 8 月结婚，没有替代方案」压成「有风险」就叫砍——**观众要的是细节，不是形容词。**

一块板的信息量按这个估：**1 行小标题 + 2~4 个块**。只有一个块的板，先问自己是不是砍多了。

**第 ③ 步是分水岭。**「渠道下沉很重要」没人反对（共识）；「一线见顶，增量全在三四线」才有人反对——那才是主张。

**主张是要付代价的判断，没有代价的判断只是描述。**

### 一个真实的反差

原文：

> 只靠一线城市，到明年大概只能覆盖四成用户；把渠道下沉到三四线，会翻到七成以上。

| | 屏幕字 | 读起来 |
|---|---|---|
| 目录型 | 渠道策略 / 市场分析 / 结论 | 一份目录 |
| 提炼后 | 一线 40% → 三四线 70%+ | 一句话 |

两版信息量相同，区别只在**有没有压**。目录型对每句话都成立，所以对观众什么也没说。

**别把这条读成"目录不能做"。** 能做的是**真的目录**——它就是全片那 3~6 章的名字，
放在片头告诉观众接下来去哪儿；而上面这个反例是**拿目录的字冒充结论**，两回事。

## 五、认关系：这句话是哪种结构

**你在这里认出来的词，就是写进脚本的 `kind`。** 它是本文件和风格 `spec.md` 之间唯一的对接点。

| 口播在说什么 | `kind` | 画面要承担 |
|---|---|---|
| "从 A 变成 B" | `转化` | 方向 |
| "不是 A，是 B" | `对照` | 对立 |
| "第一…第二…第三" | `三步递进` | 顺序 |
| "涨了 37%" | `大数字` | 单一数值 + 归因 |
| "其中三线占一半" | `占比` | 部分与整体 |
| "从 2023 到 2026 一路走高" | `趋势` | 变化 |
| "A 比 B 高" | `数值比大小` | 量差 |
| "所谓 X 就是 Y" | `关键词 + 释义` | 定义 |
| 反复出现的那个核心词 | `关键词` | 焦点 |
| 全片目录 / 章节提纲 / 跨章节要点 | `目录` | 全局位置 |
| "接下来讲第二点" | `章节标记` | 位置 |
| "已完成六成" | `进度` | 完成度 |
| 金句、结论 | `引语` | 分量 |
| "三个原因：…" | `清单` | 并列 |
| "A 组和 B 组差多少" | `数字对比` | 落差 |

**怎么选：**

- 口播里有方向（"变成"、"导致"、"下沉到"）→ `转化`
- 两块对等、没有方向 → `对照`
- 有先后顺序 → `三步递进`
- 只有一个数字，没有对照对象 → 先确认它有没有"跟谁比"；没有就退回第三节，这句可能不该做点

### 三个最容易搞混的

| 你手上 | 是不是 | 判据 |
|---|---|---|
| 全片要讲哪几块 | `目录` | 片头必给。条目 = `meta.outline` 整张表 |
| "这件事主要看三个方面" | `目录` | 概括句 + 三条散在后面几十秒里。**两个条件都要** |
| 现在讲到第几块 | `章节标记` | 只报**一个**位置（「02 · 渠道结构变化」），一句话的事 |
| 这一句里数了三个原因 | `清单` / `三步递进` | 条目**在这一句里**就列完了，不跨章节 |

**`目录` 和 `章节标记` 经常挨着出现**（先报整张地图，再标一个当前位置），但它们是两个点、两种画面。

### `关键词` 什么时候单独成点

**判据是"反复"和"承载"，不是"重要"。**

| 该单独出来 | 不该 |
|---|---|
| 同一个词在全片出现 **≥3 次**，且每次都靠它撑住讨论 | 只出现一次的名词 → 用 `关键词 + 释义` |
| 整段是在解释/围绕这一个词展开 | 句子里的普通主语、宾语 |
| 是说话人自己的提法（造词、黑话、内部叫法） | 观众早就懂的通用词 |
| 一章的落点就是这一个词 | 一章里出现了五六个并列概念 → 那是 `清单` |

**一条片子里 `关键词` 不超过 3 个。** 到处单独成点就等于没有重点。

`关键词` **不做释义**——它是把那个词**单独拎出来提醒一次**，让观众记住"这一节的核心是这个"。
要解释一个词是什么，那是 `关键词 + 释义`（有 `def`）。

**选错不会报错，只会让画面说错话。** 关系和句子，只能有一个承担——如果口播已经说了"不是 A，是 B"，画面再摆一遍文字对比就是重复；画面该承担的是**对立**这个形状。

## 六、定时间：落在第几秒

| 类型 | 入点 |
|---|---|
| 具体数值（`大数字` / `占比` / `数值比大小` / `进度`） | 那句数字**说完之后 +0.3s** |
| 结构与关系（`转化` / `对照` / `清单` / `三步递进` / `章节标记`） | 它要讲的那句话**开始时** |
| 概念 / 名词（`关键词 + 释义` / `关键词`） | 与口播**同步**（首次出现的新名词） |
| 金句（`引语`） | 金句的**后半句**落下时（前半句是铺垫，卡在后半句整句才读得全） |
| 全局（`目录`） | **比它要支撑的那一段还早**：全片目录贴片头（第一条口播前后 1s 内）；局部提纲贴**概括句说完之后 +0~1s**（钩子一落，提纲就跟上） |

**分界线是"会不会剧透具体数值"。**

- **数值必须后置**：观众还没听到 10 万，屏幕上先冒出"10 万"，这一下就废了
- **结构必须前置**：转化、对照、清单是在给这段话搭架子，架子要在话**开始**的时候就在。
  等到说完才出，画面永远慢半拍——观众听到的是"首付只有 10 万"，看到的是另一件事，
  对不上就是这么来的
- **架子比结构还要早**：`目录` 是架子的架子。等片头讲完第一个结论才报目录，那已经不叫全局视野了

一句话：**先给架子，后给数字。**

- 停留 **3~5s**：素材自己撑住，不跟着句子结束。**多行的点按行算**，
  每行差不多 1.5~2s（四行清单 ≈ 7s 是正常的，不是拖）。**`目录` 按条数算**——
  5 章的目录 ≈ 9~11s，逐条点亮要吃时间，压到 4s 就变成"啪"一下全出来，等于没呈现
- 相邻点之间留 **≥1.5s 纯透明空档**：让实拍主体露出来。**空档超过 8s 就说明漏了点** —— 观众会以为这条片子没做
- 点与点**不重叠**：一块板同一时刻只有一组元素
- **盖到片尾**：最后一个点的 `end` 距音轨结束不得超过 **6s**。末尾空一大截，等于没做完

**时间码永远来自音轨，不要估。** 拿不到 SRT 就先停下问用户要。

## 七、定密度：一条片子出几个点

| 体裁 | `contentType` | 原片长什么样 | 每 60s |
|---|---|---|---|
| 数字型 | `data` | 研报 / 口播 / 复盘 | 8~12 |
| 叙述型 | `narrative` | 故事 / 案例 / 科普 | 6~10 |
| 剧情型 | `drama` | 剧情 / 短剧 | 3~5 |
| 观点型 | `opinion` | 观点 / 评论 | 10~14 |

**往上沿走，别贴下沿。** 落在下沿的产物，观感就是"半天不出东西"——密度表的数字是**及格线到上限**，不是"够用就行"。

**超上限不是"内容多"，是叠加层变成了第二块屏。**

**`目录` 不计入密度。** 它是同一张地图可能复现的东西，不是一句口播的内容——
一条 137s 的片子加 1 个片头目录 + 一个有概括句的地方一个提纲，内容点该是 20~30 个还是 20~30 个（数字型档位）。
`章节标记` **要算**：它占屏 3 秒多，是实打实的一个素材点。

## 八、交付：脚本 JSON

```json
{
  "meta": {
    "style": "soft-relief",
    "title": "渠道下沉带来的结构性增长",
    "ratio": "3:4",
    "duration": 137.0,
    "contentType": "data",
    "outline": [
      { "idx": "01", "title": "渠道结构变化", "start": 12.0, "end": 48.5 },
      { "idx": "02", "title": "一线为什么见顶", "start": 48.5, "end": 96.0 },
      { "idx": "03", "title": "三四线怎么接", "start": 96.0, "end": 137.0 }
    ]
  },
  "voiceover": [
    { "i": 1, "start": 0.0, "end": 3.8, "text": "我们先看一组反常的数据。" }
  ],
  "points": [
    {
      "i": 1,
      "kind": "目录",
      "form": "折叠",
      "kick": "这条片子的三段",
      "start": 0.6,
      "end": 10.4,
      "blocks": [
        { "idx": "01", "title": "渠道结构变化" },
        { "idx": "02", "title": "一线为什么见顶" },
        { "idx": "03", "title": "三四线怎么接" }
      ]
    },
    {
      "i": 2,
      "kind": "章节标记",
      "form": "括标",
      "kick": "第一章",
      "start": 12.0,
      "end": 15.6,
      "blocks": [{ "idx": "01", "title": "渠道结构变化" }]
    },
    {
      "i": 3,
      "kind": "转化",
      "form": "折叠",
      "kick": "对话到建议",
      "start": 12.6,
      "end": 16.8,
      "blocks": [
        { "t": "一线城市", "v": "40%" },
        { "arrow": "渠道下沉" },
        { "t": "三四线", "v": "70%+" }
      ]
    },
    {
      "i": 4,
      "kind": "关键词",
      "form": "无壳",
      "kick": "核心词",
      "start": 50.2,
      "end": 54.0,
      "blocks": [{ "word": "渠道下沉" }]
    }
  ]
}
```

- `blocks` 是数组，长度和键由 `kind` 决定——**每个 `kind` 要什么，写在风格的 `spec.md` 里**
- `kick` 是这张卡的小标题（**每张卡都要有**，≤12 字）。它写"这卡在讲什么"，
  `blocks` 写"具体是什么"，**两个不许重复**（✓ kick「定义」+ term「业务闭环」）
- `kick` 不是给人念的，是给观众**扫**的。写成一句完整的话就是写错了
- `form` 是这个点想长什么样，用**白话名**写，**永远不许写类名**。
  **这个风格有哪几档、各自长什么样、什么时候用，写在该风格 `spec.md` 第五节的「形态 / 壳」表里**
  （`neon-terminal` 是 `带底` / `折叠` / `亮条` / `括标` / `无壳`；`soft-relief` 是 `凸起` / `凹陷` / `无板`）。
  还没定就用风格 `spec.md` 里第一档，别自己编一个名字
- `form` 只是"我打算用什么样的形式"这个标签；**具体换算成哪个类名、配哪个动效，是生成 HTML 那一步的事**
- **相邻两个点的 `form` 尽量不一样**。同一个 `kind` 连着出现，就靠换 `form` 拉开——
  21 个点全长一个样，观众第三眼就不看了
- `目录` 分两遍用：
  - **片头那一遍省略 `cur`**，把 `meta.outline` 整张表报完，全部按"未讲"处理
  - **局部提纲**（有概括句那次）给 `cur`：值是**这几条自己的 `idx`**，序号小于它的算"已讲"、
    等于的是"当前"、大于的是"未讲"。条目的 `idx` 用**这一段内部的序号**（`01` / `02` / `03`），
    不必和 `meta.outline` 的章节号对齐
  - 同一条逻辑走到第二、第三条时想再报一次，就**只换 `cur`**，条目不动
- `meta.style` 决定用哪份 `spec.md`；`meta.ratio` 恒为 `3:4`（透明素材的画幅）
- 再给一份同名 `.md`，给人看

## 九、自检

- [ ] `meta.outline` 有 3~6 章，`title` 是话题不是占位，字数是 ≤8
- [ ] **片头有 `目录`，它比第一个内容点还早**（硬要求）
- [ ] `目录` 的条目与 `meta.outline` 逐条一致（序号 + 标题）
- [ ] **口播里每一句"我讲三个方面"式的概括句，都已配上一个 `目录`**；反过来，
      没有被概括句点名的并列几条，**没有**替它总结成提纲
- [ ] `章节标记` 的 `idx` / `title` 在 `meta.outline` 里有对应项
- [ ] 每个点都指得回一句口播，时间上贴着
- [ ] 每个点都**承担一个关系**（对照 / 流向 / 递进 / 占比）。只有一个孤零零的值，退回第四节重压；
      `引语` / `章节标记` / `目录` / `关键词` 例外，它们本身就是一件事
- [ ] `kind` 是从第五节那张表里挑的
- [ ] `关键词` 不超过 3 个，每个都满足"全片出现 ≥3 次"
- [ ] `start` 落在句子结束后 +0.3s（数字型）
- [ ] 停留 ≥3s，相邻空档 ≥1.5s，点与点不重叠
- [ ] 密度落在 `contentType` 的档位内（骨架点不算）
- [ ] 时间码来自音轨，不是估的
